# second-take

> **English (short):** a method layer that turns a long story into shootable shots and reproducible prompts — criteria and gates, not a prompt collection. Python 3.11+, runs locally, no telemetry, no network calls of its own. Start with `python tools/bootstrap.py --check`. → [English README](README.en.md)｜Code Apache-2.0 ／ docs CC BY-SA 4.0.

把一部长篇拆成能拍的镜头，再把每个镜头写成能复现的提示词。每一步都有判据，出问题能看出停在哪。

> 拍片时 `Take 2` 是「再来一条」；日常英语里 `my take` 是「我的看法」。这个名字说的是它真正在做的事：**不断重生成，直到对为止**。

## 三步开工

1. `git clone` 本仓库，装 **Python 3.11+**（Windows / macOS / Linux 都行）。先跑一次自检：

   POSIX：

   ```bash
   cd <repo>
   python3 tools/bootstrap.py --check
   ```

   PowerShell：

   ```powershell
   cd <repo>
   python tools/bootstrap.py --check
   ```

   退出 **0** 就说明环境合格；不是 0 它会逐条告诉你缺什么、怎么补。**该建的目录它会自己建**，不用你猜。

   > **分发包只有一个 zip，文件名带 `-win`——那是历史命名，不是平台限制。** 包里是纯文本与 Python，没有二进制。
   > macOS／Linux 直接 clone 本仓库就行，不必等一个「mac 版」。

2. 打开 `开工提示词.md`，把那段话整段复制给你的 AI。它会先问你三个问题（原文在哪／文体／与原著的关系），然后带你出第一张图。

3. 第一张图出来之后，再回来看这里。**在此之前你不需要读任何文档。**

出不来、或者卡在某一步：[提 Issues](../../issues)，带上 `python packaging/_doctor.py` 的输出。只想提建议就选「建议」模板，不用写代码。

## 它会给你什么

- 一段故事 → 分镜 → 可复现的提示词 → 一张图，中途不用回来问人。
- 每一格都写着「为什么这样拍」，不是抽卡抽到为止。
- 每一环都有验收：哪一步算过、没过时找谁拍板。

## 三条前提

不认同这三条，后面的规范会很别扭：

- **长线项目靠台账，不靠记性。** 哪一版算数只能有一个台账，否则旧版本会以「摘要」的样子反扑回来。
- **草稿和原文物理隔离。** 自检全通之前原文一个字不动，锚点污染不可逆。
- **角色只用他自己知道的信息做判断。** 作者知道的，不能从角色嘴里漏出来。

## 它凭什么说自己干净

不是「我们检查过了」，是三条你能自己跑的命令：

```
python packaging/_doctor.py                            # 我在哪一侧？缺什么？这一条谁都能跑
python packaging/_triage.py .                          # 结构类信号（密钥／本机路径）照常给
python packaging/_leakscan.py --words <你的词表.txt>    # 拿你自己那份词表，连历史一起扫
```

**第一次 clone 下来先跑 `_doctor.py`。** 它会告诉你这里是「骨架侧」，没有词表是正常的——词表属于项目，不属于这个库。

**本库不带任何禁用词表。** 因为它必须写出要禁的词，留在库里等于自己泄一次——2026-11-21 把它搬出了仓库：CI 从仓库 secret 注入，本地由你给 `--words`。所以第三条命令必须由你提供词表；**不给就退出码 2——那叫没查成，不是干净**。

`_triage.py` 在骨架侧同样给 **2**：没有词表，它判不了专名。这两个 2 都是设计，不是缺文件、不是装坏了。

这条链是被事故逼出来的：这个仓库公开的第一天，就有一句「解释文字」把三个真实组织名带了出去，而当时的检查是全绿的。经过、覆盖率、每一条是怎么踩的，都在 [`docs/为什么值得信.md`](docs/为什么值得信.md)。不用先信，那三条命令可以自己跑一遍。

要改代码、发版、加检查器：看 [`docs/maintain/维护方法.md`](docs/maintain/维护方法.md)。

那里有发版五步、13 条真踩过的坑、回执格式，以及一条机器强制：**改了 `gate/`／`packaging/`／`tools/`／`.github/` 任何一个，就必须同时改那份文件**，否则提交信息里要写 `[no-procedure-change: 理由]`。

**它不依赖任何人的机器**——没有盘符、没有用户名，拷到别的机器照着做就行。

## 边界与免责

**这份仓库不是提示词大全，是判据与门槛。**

本工具不做生产环节替代，只会根据您已经在使用的方法，进行「可判」的机读语言规则生成，依此指出操作的矛盾点及与判据的冲突点。

本仓的负责边界为：效果未达预期时，帮您判断是提示词问题还是其他因素问题。如您已经在使用成熟的提示词 skill，请继续使用——您可以让模型按本仓规则，把您该次处理的做法整理成几条判据，用来进行下一次判断。

本仓库里的提示词经验，只在两种时候用：

1. **校准**：检查 skill 产出的词有没有自相矛盾（一边要虚焦、一边禁虚焦）、有没有把文学词量化成数字、有没有和判据打架；
2. **立判据**：决定这一格算不算过。

**分工一句话：skill 管生成，本仓库管判好坏。** 拿这份仓库当提示词模板抄，反而会把它用废。
