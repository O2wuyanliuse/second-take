# 为什么值得信

> 这里记的是这个仓库的病史，不是使用说明。怀疑的时候再来读；不怀疑的人不该在第一屏交这份学费。

---

## 关于文中的 `G-xxx`

你会看到 `G-140`、`G-302` 这类编号。它们是原作者内部台账的条目号，**本仓库不包含那份台账**。

保留它们是有意的：每一条规则后面都跟着它踩过的那个坑，编号是溯源用的指针。读的时候把它们当成「这条规则的案发现场」就好，不需要找到原始条目。

## 两次事故：公开第一天，和第二天

**一次真实事故，留在这里当警示（2026-11-11）**

这个仓库第一次公开时，`packaging/_pack.py` 里一句解释「为什么某个脚本不能带出去」的说明文字，
把**三个真实组织名**写了进去。而当时的打包流程是**全绿**的——因为它扫的是「包的结构」，
不是「内容的来历」。修正它需要重建整条公开历史，因为**公开仓库的泄露不可逆**：
一旦被 fork、被缓存，删掉 HEAD 也删不掉过去。

**然后是第二次（2026-11-12）。** 清完那一处、仓库转私有之后，拿项目侧的词表回头一扫，
同一个仓库里还有四处：`_nounlist.py` 的 docstring 用真名复盘那次事故、
`_triage.py` 的正则里写死了一个本机目录名。**同一个病因，隔了一天又长出来。**

两次的共同点：**它们都是自己写出来的，不是从项目搬过来的。** 所有「比对私库与骨架库」的闸，
查的都是搬运环节，看不见自行生长的文字。所以这次不只修文字——补了一道 `_leakscan.py`，
让「本库自己有没有残留」变成一条**能跑的命令**，并且默认连全部历史一起查。
修一个洞和补一道闸，区别在于第三次还会不会发生。

## 门禁：只跑适用于本库的项，结论自带覆盖率

```bash
python gate/_gate.py          # 两行结论，含覆盖率
python gate/_gate.py --each   # 逐项，看每个跳过项的**理由**
```

`gate_profile.json` 声明哪几项适用。不在里面的**不算通过，只算跳过**，结论会印覆盖率：

```
⚠ 部分通过：18 项 ｜ 绿 3 ／ 跳过 15 ／ 提示 0 ／ 阻断 0
   跳过 15 项不算绿：本页只覆盖 3/18 项（17%）
```
（上面是示例。**具体数别抄**——脚本会增减，抄进文档就变成又一个「过期的数」。跑一次看输出。）

**为什么不干脆做成「全绿」**：那些跳过项要的正文／台账／锚定表／抽卡记录在这个库里根本不存在。
让它们跑，只会得到一堆假红（实测 `_anchor` 报 35 条断链，全是「子集里没有」）；
把它们从分母里删掉，又会得到一句「17 项全过」的假结论。**印出覆盖率是唯一诚实的做法。**

**跳过项分三类，别当成 15 件事看。** 判据不是「本库有没有这个对象」——那问法会得出一个循环论证：
对象不存在，恰恰因为补丁长在项目里没提炼上来。

| 类 | 条 | 是什么 | 怎么处理 |
|---|---|---|---|
| **A 作品内容** | 4 | 正文／定稿／原文／花钱史——天生属于某一部作品 | **结案。** 提炼进公共库既无意义也无版权 |
| **B 本库该跑** | 5 | 查「这个包自己干不干净」：层级纯度／skills 结构／五处副本／不发布基线／决策证据栏 | **对外发布前必补** |
| **C 项目侧工具** | 6 | 制度与机制：状态源／锚定表／资产台账／作废词／常量台账／作业状态 | **随包分发脚本＋空白模板**，在使用方的项目里跑；本库没有活数据，跑只会全红 |

「长在骨架上」不等于「都在本库身上跑」——这是这三类唯一的区别。
逐条理由见 `gate_profile.json` 的 `_三类` 字段。

真正在跑的三项：

- **`_redline` 版权红线**——它第一次跑就抓到一个真缺口：本库当时缺「版权与开源红线」和「发布前检查清单」两份文件，已补上。这条检查跟任何具体作品无关。
- **`_orphan` 孤儿件**——没有任何 md 是「谁都没提到」的。
- **`_links` 引用断链**——两遍扫：带斜杠的路径、`[类别]名` 形式的落点。窄口径，只认 23 类前缀（`DEBT` 词跳过），所以它不会拿项目专名去误报。

**注意模式差异**：本库是公开库，`redline.json` 里写着 `{"公开库": true}`，
于是「有没有 LICENSE」的期望反转——公开库**必须有**，私库**不该有**。
同一条判据，两头相反，所以它是配置，不是规则。
