# gate/_e0.py 原始模块文档

来源：`gate/_e0.py`。本文保存外搬前的完整说明、事故史与表格；代码内只保留运行用法和本页指针。

_e0.py · 投喂登记（E0·1–E0·3）有没有做过

为什么有这一项（2026-11-20 冷启动实测）
    `AGENTS.md` 写着「按 E0–E8 推进，不跳步」，但那只是**一句话**：
    门禁里没有任何一项在问「E0 登记做没做」。于是冷启动窗口拿到一段正文，
    直接跳到 E2-2 美术定调 + S01 镜表 + E3-0 判格——**E0 的三行登记与 E1 裁决一条没做**，
    而门禁照样报绿。这正是「文档说要，机器不查」。

    这条闸只问一件事：**投喂台账在不在、三样事实齐不齐。**
    它不问三样写得对不对——那要靠人（E0·1 的四问是递给作者的），机器只判「有没有」。

判什么（三样，缺一样就阻断）
    1. **原文在哪**：这份字从哪来（文件路径／投喂来源）
    2. **文体**：是正文，还是设定相关，还是混合
    3. **与原著的关系**：原创自写，还是他人作品（他人作品还要出处）

    三样都写在 `00_原著/投喂与授权台账.md` 的**同一行**里（见 `Agent框架/环节表_文字到可视化_v1.md` E0·1–E0·3）。
    本脚本不解析表格列序，只查「三样要素有没有出现过、有没有一行真的填了字」——
    换项目的台账表头不同也能用，**判形状不判内容**。

退出码（与全库同语义）
    0 ＝ 三样齐、有数据行
    1 ＝ 有 `00_原著/` 但台账缺、或三样缺、或没有数据行  ← 阻断：分格/定调不许开始
    2 ＝ 还没有 `00_原著/`  ← 提示（本库是方法仓，或项目还没建档）。**提示不是通过。**

为什么「没有 00_原著」只给提示、不判红
    本仓库按设计不含作品，`gate_profile.json` 里一大票检查都因为「对象不存在」而跳过。
    在这里判红只会造一个假红，然后被人学会绕过（`_drift.py` 的 C2/C3 就是那么死的）。
    但**提示必须印出来**：它提醒的正是冷启动踩的那一步——没有 00_原著，就没有 E0 登记，
    那么后面所有产物都没有「依据哪一份原文」这句话。

用法
    python gate/_e0.py            # 查本仓库
    python gate/_e0.py --gate     # 同上（门禁调用口径，输出更短）
    python gate/_e0.py --self     # 自测：五种形态，全在内存里造，不写盘
