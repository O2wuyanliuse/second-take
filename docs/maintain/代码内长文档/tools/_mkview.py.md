# tools/_mkview.py 原始模块文档

来源：`tools/_mkview.py`。本文保存外搬前的完整说明、事故史与表格；代码内只保留运行用法和本页指针。

清单 → 可填视图生成器（通用层）

为什么要有它（2026-11-01）：
    「该给视图」这条纪律写满了框架，但每张件都是手写的。手写的两层后果：
      ① 会漏——22 张视图里 19 张停在 10-31 前。不是不想做，是每次都要重做。
      ② 会漂——每份的复位钩子各写各的，L1.2 五条全靠人逐份核。
    把「清单 → 合规件」做成程序，视图就从「要记得做」变成「顺手跑」。

它做什么：
    读一份 md 表格（一条一行），产出一张可填视图：
      · 阶段一「只读」：先让人把问题看完，开关是锁的
      · 阶段二「解锁」：点一下才可作答——防「没读就勾」
      · 五条硬要求全部内建：复位钩子／defaultChecked／pageshow／徽标／禁 Storage
      · 回执裸文本 ＋ 必答校验

输入格式（表头名模糊匹配，**不认列序号**）：
    | 编号 | 问题 | 依据 | 选项 | 建议 |
    |---|---|---|---|---|
    | Q1   | …    | …    | 采纳/覆盖 | …    |

    「问题」列必须有，其余可选。选项用 / 分隔。
    **按表头名取值，不按 cells[N]**——10-31 那次「位置当含义」的错，就是这么来的。

用法：
    python _mkview.py 清单.md -o "[视图]XXX.html"
    python _mkview.py 清单.md -o out.html --title "E0·6 对齐扫雷" --mode t2
    python _mkview.py 清单.md -o out.html --options "采纳/覆盖/作废"

模式默认值（--mode）：
    t1 → 采纳／覆盖／作废（逐条裁定）
    t2 → 已定／未定（二元拍板）
    也可用 --options 直接给，覆盖 --mode

它不做什么：
    · 不判断内容对不对——它只管形态
    · 不替你选——选项来自清单，它只负责摆出来
    · 不管输入从哪来——台账、清单、手写表格都行
