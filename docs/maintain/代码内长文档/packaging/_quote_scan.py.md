# packaging/_quote_scan.py 原始模块文档

来源：`packaging/_quote_scan.py`。本文保存外搬前的完整说明、事故史与表格；代码内只保留运行用法和本页指针。

_quote_scan.py — 查「分发包里有没有正文原句」，并卡住上限。

    python packaging/_quote_scan.py <目标目录>
    python packaging/_quote_scan.py <目标目录> --strip     就地替换（慎用）
    python packaging/_quote_scan.py --selftest             反向验检测器本身

退出码：0 在限内／1 超限／2 没得查（目录空或原文缺失，**不是通过**）

## 为什么非要有这个脚本

`_verify_package.py` 的 V3 查的是**专名**（角色名）。但专名只是「名字」这一种泄漏，
**正文原句是另一种**：它不含任何名字，V3 一律放行。

实测（2026-11-02 首次）：包内 30 处、共 300 字命中原文，最长连续 26 字。
分布主要是两类——**小说里的台词原句**、**环境描写原句**，都夹在「标准件」的教学举例里。
V3 当时是绿的。**绿的是它查的那一项，不是整件事。**

## 阈值从哪来（不是拍的）

首次测量：30 处 / 300 字 / 单处最长 26 字。
上限取 **单处 40 字、总量 450 字** —— 允许合理增量（再加两三个示例不至于拦），
但**不允许翻倍**。真要加，得先改这里并写明理由，那比悄悄变多好。

## 一个必须防的坑：零覆盖假绿

本脚本第一次写出来时报「0 处残留」，实际有 30 处。原因是目标目录用了 `/tmp/...`，
而 Git Bash 的 `/tmp` 与 Python 眼里的 `D:\tmp` 不是同一个位置——
`os.walk` 对不存在的目录**不报错，返回空列表**，于是「一个文件都没扫」被说成了「没有残留」。

所以本脚本有三道防线：
1. 目录不存在 → 直接退出码 2，不装作通过
2. 扫到的文件数少得离谱（< 20）→ 退出码 2
3. 原文池为空 → 退出码 2（没有尺子，量出来的 0 不算数）
