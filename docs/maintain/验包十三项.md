# 验包十三项（文件名沿用，现十四项）

本文从 `packaging/_verify_package.py` 的长 docstring 搬来；代码里只留指针。

## 它为什么存在

`_pack.py` 用白名单打出来的包，理论上就是对的。**但「理论上」在这件事上不够。**

今天已经出过一次同类事故：`skills/` 里两份规则副本跟项目 `07` 悄悄分叉 6 条，条数编号全对得上，肉眼看不出（`G-125`）。
而这次要防的是它的极端版——**分叉出去的东西一旦发出去就收不回来**。

所以：
> **打包的人不许靠「我记得都剥干净了」，要靠这个脚本说「干净」。**

## 验包项查什么（现十四项）

| # | 查 | 不过的后果 |
|---|---|---|
| V0 | 真的扫到了文件（≥60 个） | 路径写错也报「干净」——零覆盖假绿 |
| V1 | 必需文件齐全（人读入口还卡最小体积） | 装不上／用户看到空说明 |
| V2 | 没有正文／过程稿／备份／缓存混进来 | **泄稿** |
| V3 | 全部文本里没有项目专名 | **泄设定** |
| V4 | 脚本能跑（不崩） | 装完一跑就 Traceback |
| V5 | 没有凭据 | 泄 token |
| V6 | 目录结构对（`00_原著/` 在，脚本在它下面） | 所有脚本推错根目录，集体失效 |
| V7 | 免责声明在四处入口原文在场 | 分发的前提没了 |
| V8 | 文档没有整段连贴两遍（判据在 `_dupcheck.py`，这里只调用） | 补丁叠层：同一句警告贴两遍，读者以为你没校对 |
| V9 | 版本号全包一致 | 收包人手里是 v0.2、说明书写 v0.1，出问题对不上号 |
| V10 | 包内框架件全是通用层 | **项目内容随包出门**。混合层那一档已取消——留着它等于给项目内容开正式出口 |
| V11 | 包里没有「这台机器的坐标」 | 收包人照着 `D:/某人/…` 找不到东西，**以为自己装错了** |
| V12 | 人读入口不挂台账编号（`G-xxx`） | 包里的台账是空模板，他翻不到那个号，**以为自己少拿了东西** |
| V13 | 包内 `MANIFEST.sha256` 自洽（逐文件 sha256、不含自身、行数＝文件数−1） | 包被篡改／缺文件却看不出——自洽清单失效 |

V3 的词表**从 `_collab.py` 现读**，不在这里抄一份——抄一份就是又造一对副本，而副本一定会漂（`G-125` 的教训）。

这张表是**人读的唯一入口**：加一项就改这里，别只加代码。表比代码容易忘，而忘了改表的后果是「新闸没人知道它存在」——等于没有闸。

## 红了怎么办

| 项 | 先看哪 | 通常怎么修 |
|---|---|---|
| V0 | 传进去的路径 | 是路径错了，不是包干净 |
| V1 | `_pack.py` 的 `TEMPLATES`／`INCLUDE_STD` | 补进计划表 |
| V2 | `EXCLUDE_FILES` | 该剔的没剔，或模板里混进了正文 |
| V3 | `_collab.py` 的专名表 | 补脱敏规则（见 「待脱敏清单」（已移出仓库））。**别改词表**——改词表等于改判据，下一次换个名字照样漏 |
| V4 | 脚本本身 | 先 `python -m py_compile` 逐个编；再看是不是脱敏把字符串改坏了 |
| V6 | 顶层目录 | 脚本必须与 `00_原著/` 同层 |
| V9 | 版本号常量 | 一处改了别处没改 |
| V10 | 文件头的 `> **层**` | 要么改声明，要么把项目那一半搬去项目层文件 |
| V11 | 那一行是「示范／反面示例」还是真坐标 | 前者 → 行内加 `[坐标-ok]` 或进 `V11_EXEMPT`；后者 → 改成相对包根 |
| V12 | 那个号在入口页里当什么用 | 当「凭什么这么改」的溯源 → 删号，留下日期与事由；当教学示例 → 挪进规范正文（`Agent框架/` 里不查） |
| V13 | 哪一行 sha256 不符／缺哪个文件 | 重新打包（`tools/build_public_package.py`）；清单由打包生成，别手改包内文件 |

## V11 的两种放行方式

1. **行内写 `[坐标-ok]`** —— 跟着行走，改字不失配。**默认用这个。**
2. **加进 `V11_EXEMPT`** —— 只在「同一份文件里好几行示范路径、逐行加标记太吵」时用。

## 它查不了的

- 每份 md 里的**措辞**是不是在讲这个项目（`_collab` 自己也只证「字面上没有专名」）
- 包好不好用（那要真装一遍）
- 漏了某个**该带但白名单里没列**的文件——它只知道「多」和「缺必需」，不知道「缺想要」

## V4/V4a：为什么先编译、为什么在副本里跑（G-147）

包里所有脚本都要跑，不只是两个。脱敏会往脚本里做文本替换，最容易的坏法是「改完还能 import，但一执行就抛异常」。判据只有「不许出现 Traceback」；退出码 0/1/2 都可能是正常结论，1 可能是查出了问题，2 可能是参数不对。

标题里的脚本数必须现算，不能写死。2026-11-02 从白名单剔掉两个脚本后，实际只有 20 个，旧标题还在说 22；当场就过期的数字比没有数字更糟。

2026-11-02 外部实测曾在包里跑 `_selftest.py`，直接 SyntaxError，而 V4 只找输出里的「Traceback」；语法错不打印 Traceback，于是「全部跑通」和「根本没编译过」在旧 V4 眼里长得一样。V4a 因此先逐个编译，再谈跑不跑。

跑脚本必须跑在副本里，不能跑在被验的包上。`_mkview`／`_board` 会往 `00_原著/` 写 `[视图]*.html`；曾在验完后多出两个文件，而 zip 在验完之后打，两个没被验证的文件就这样进了发行包。原则是：验证不许改被验的东西，跑坏了也不该在真件上留痕。

## V11：本机坐标判据的来历（G-300/G-302）

V3 查项目专名，查不到路径。这类泄漏的特点是「引用的东西明明在包里，只是坐标写成了绝对路径」，收件人点开是空的，会以为自己装错了。判据不是「有没有提到某个词」，而是「这个坐标换台机器还成不成立」。

两条克制都来自实测：

1. 不把裸词判死。说明书里「出现 AppData／Temp 就说明你装进了临时目录」是判据本身，不是坐标；路径形态才红，裸词只提不拦。
2. 盘符后面必须跟一个真字符。第一版写 `[A-Za-z]:[\\/]`，把脚本里的正则字面量误判成盘符路径；判据松一格，工具就会咬自己。

确实需要举反面路径例子的行，可以行内写 `[坐标-ok]`，或加进 `V11_EXEMPT` 逐条列名，不许通配。

豁免用 `needle` 认语义锚点，不认路径值（G-302）。原写法拿 `D:\我的创作` 当 needle；说明书把示范盘符改成 `E:\作品`，豁免就失配。判据钉在会变的东西上一定会误报，所以钉「这行为什么被放行」那句话；那句话改了，说明语义变了，本来就该重新看。
