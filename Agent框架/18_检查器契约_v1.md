# 18 · 检查器契约（通用）

> **路径说明**：文中出现的 `00_原著/checks/`／`templates/checks/` 等是**项目实例**的摆法，换项目照自己的结构改（详见 `11_分发说明_v1.md` §四）。

> **层**：**通用层**——整份可搬。文中脚本名是**项目实例**，换项目按 §六 改参数。
> **读者**：写检查器的人（AI）。**每次新增一项检查前读一遍。**
> **来源**：一个项目里长到 43 个脚本、49 项检查之后，把「一条检查怎样才算合格」反推出来的（2026-11-16）。

---

## 一、一条检查必须自报范围

**输出里必须有一行 `[scope]`**，写清：读了几份、查了几项、跳过了什么、为什么跳。

> 没有 scope 的检查，读者无法判断"绿"是"全过"还是"一个都没查"。

**理由**：一晚里三次"绿得毫无内容"——图片路径没人查、检查器读错基准目录、项数三处各写各的。**它们都不报错，只是安静地不干活。**

---

## 二、四条硬契约

| # | 契约 | 违反的后果 |
|---|---|---|
| 1 | **自报范围**（`[scope]` 一行） | 绿无法判断 |
| 2 | **对象不存在时走 `_unset`，不许报绿** | 换项目时"绿"是假的，因为它根本没找到对象 |
| 3 | **自包含可跑**（`python xxx.py` 直接出结论；有分组包时**包随主脚本一起走**） | 只能靠总闸，出错时无法定位 |
| 4 | **退出码有语义**：`0` 全过 ／ `1` 有错 ／ `2` 配置未完成（不是质量问题） | 把"没配完"当成"做错了"，人会去修不存在的错 |

**`_unset` 的三种用法**（写清楚，别混）：
- 对象不存在 → 「这一项在你项目里才有意义」
- 找不到源文件 → 「读不到 X，跳过」
- 判据失效（解析出 0 条）→ 「判据失效，等于没查」

---

## 三、新增一项检查，必须同时交三样

1. **检查本身**（带 `[scope]` 与退出码）；
2. **一条反向用例**：故意造一个错，它必须红——**这是唯一能证明它真在查的办法**；
3. **一句「它抓不到什么」**：写在函数注释或输出里。

> 第 3 条最常被跳过，而它决定了别人会不会误以为"全绿＝全对"。

**实测价值**：一晚里两个新检查，都是靠"造错"才发现第一版是错的——一个把路径基准写错（静默变绿），一个把两栏的锁报成"缺第 1 栏"（误报）。

---

## 四、五类固定坑（写完先自查）

| 坑 | 表现 | 防法 |
|---|---|---|
| **路径基准** | 脚本在子目录被调用，项目根相对路径全线落空 → 静默绿 | 所有读文件走同一个 `rd()`，且它拼的是**项目根** |
| **行尾** | 库里 CRLF、新写的用 LF → 假 100% 差异 | 读入统一 `\r\n`→`\n`，写回按原样 |
| **竖线** | 表格单元格里写 `` `\|` `` 或 `A | B` → 列数错、整行被跳过 | 检查器切列前先数；输出里禁止裸竖线 |
| **共享底稿** | 把"大家都在改的文件"当"这条可能已推进"的证据 | 只认产物类（图／定版件），不认流水账 |
| **同义状态词** | 文档里写"未定"，而它恰是系统的状态词 | 状态词只归一个写者；说明里换同义表述 |

---

## 五、两种输出分层

| 层 | 含义 | 处理 |
|---|---|---|
| **红（P1／阻断）** | 真的错了，必须修 | 提交前修；修不动就问 |
| **提示（P2）** | 可疑，可能没事 | 只提示不拦；**报红的清单要短，提示的清单长了可以，但不能变红** |

> **反例**：把"可能没关的账"做成红 → 天天见红 → 红被无视 → 真错也漏。**红的稀缺性就是它的价值。**

---

## 六、参数（换项目改这里）

| 参数 | 本项目 | 换项目要改 |
|---|---|---|
| 项目根判定 | `_pname.py` 归一 + 各脚本 `PROJ` | 必须有**唯一**来源，不许各写一份 |
| 检查清单 | `CHECKS` 表（不手写项数） | 项数**永远从表算**，文档里写的数由检查守住 |
| 自测入口 | `_selftest.py`（127 条） | 换项目重建，**但要有"零覆盖"用例**（目标文件缺失时不许报绿） |
| 总闸 | `_gate.py`（25 项） | 换项目重排，闸与 pre-commit 用**同一份** |

## 七、脱参数：怎么把一支项目检查器变成模板

**现成模板**：`templates/checks/`（`_links.py`／`_orphan.py` ＋ `checks.config.example.json` ＋ README）。这两支是最小的一对，只依赖目录结构、不依赖业务字段。

**三步**：

1. **抽常量**：把所有「项目才知道的」收进一个配置——扫哪些扩展名、跳哪些目录、豁免清单在哪。**别让它们散在代码里**。
2. **给缺省**：没有配置文件也要能独立跑，缺省＝扫全库、**不跳任何项目目录**（宁可多报，不许静默少报）。
3. **给 `--root`**：脚本要能从任何位置被调用；路径基准永远是**项目根**，不是脚本所在目录。

**验收只有一条**：**通用版与原版在同一项目上逐条一致**——结论行数字相同，清单也要逐条相同。**数字相同而清单不同，也算失败**（判据已分叉）。

**别做的事**：把「哪些条目不算」放进配置。那会让判据按需要变松；豁免要走**带理由的清单**。

## 八、复合体怎么办：一支脚本塞了 49 项检查

**现象**：检查器长到几十项之后，它不再是"一个检查"，而是"一个检查集合"。这时**它既不能搬、也不好改**——改一项要跑全量，报红分不清是哪一类。

**判断标准**：如果它同时满足下面两条，就该拆：

1. **项数 > 20**；
2. **项与项之间不共享中间结果**（改 A 项不需要重算 B 项的数据）。

**拆分不按文件拆，按「判据对象」拆**。一个组里的项应当满足：**读同一批输入、报同一类错、能独立判定**。

示例分法（按对象，不按字母序）：

| 组 | 读什么 | 报什么 |
|---|---|---|
| 引用组 | 文档里的引用与真相源 | 断链／失实／行号漂 |
| 账务组 | 台账与通道 | 计数不符／条目超长／状态词双写 |
| 产物组 | 图／视频路径与台账 | 路径断／重复挂图／口径缺 |
| 格式组 | 单份文档的结构 | 章号重号／换行混行／列数不一致 |
| 回关组 | 开着的条目与产物时间 | 可能已推进 |

**拆完的验收**：

1. **并集不变**：所有组跑一遍的结论，必须与拆之前一致（逐条对比，不许抽样）；
2. **每组能单独跑**，且**单独跑不假绿**（缺输入时走 `_unset`）；
3. **总闸只调分组入口**，不再内联每一项——闸的职责是"跑各组、汇结论"，不是"知道每一项怎么查"。

> **一句提醒**：拆分层是**结构变化**，不是搬走。拆完还要逐组过 §七 的脱参数三步，别指望一次做完。

### 八·一 第一步先做「分组可执行」，不是物理拆文件

**顺序**：分组可执行 → 验证并集不变 → 再考虑把代码搬到不同文件。

**为什么**：物理拆文件会同时动到 import、路径基准、总闸入口——**三件事一起变，出问题分不清是谁**。而"分组可执行"只动一处：一张 `GROUPS` 表 ＋ 一个 `--group` 参数。

**必带一条覆盖自检**（否则分组表自己会漂）：

> 拿 `GROUPS` 的名字集合与检查清单比：**未归组**／**表里没有**／**重复归组** —— 三种任一，当场报红。

**验收两条**：各组项数之和 ＝ 全量项数；每组单独跑都能出结论，且缺输入时走 `_unset` 不假绿。

**实测（本项目）**：49 项 → 引用 14／账务 17／产物 4／格式 12／回关 2 ＝ 49。覆盖自检第一天就抓到一处「表里有、清单里没有」的幽灵项——**它报的那一句，比拆本身更有用**。

### 八·二 物理拆试点（2026-11-17 实测，一组）

**拆的是「回关组」（2 项）**：`check_open_stale`／`check_json_reformat` 及各自的辅助函数，搬进 `00_原著/checks/huiguan.py`；主脚本留注入与清单。

**注入顺序是命门**：

```python
_core.PROJ, _core.P1, _core.P2 = PROJ, P1, P2   # 先给同一个对象
_core.rd, _core._unset = rd, _unset
from checks.huiguan import check_open_stale     # 再导入组模块
```

反了的话，组里 append 的是**另一份列表**——报告会显示"全都过了"，因为主脚本那份没人往里写。**这类错不会报错，只会安静地变绿。**

**验收结果**：拆前拆后全量输出逐字相同（唯一差异是「换行形态 355→358 份」，因为新增了 3 个 LF 文件）。

**一处契约要改**：原写「单文件可跑」，拆完不成立——自测沙箱只抄主脚本，51 条用例全败。**改成「自包含可跑：主脚本 ＋ 它的分组包」**，并让自测把包一起抄进去。

> **一条教训**：物理拆的第一道坎不是代码，是**夹具**。判据没错、代码没错，错在"测它的环境少了一个目录"。

### 八·三 第二个试点：产物组只拆出 1 项，另外 3 项拆不动

**实测**：产物组 4 项里，只有 `check_style_lock` 的依赖闭包是干净的——它只用到 6 个 `STYLE_*` 常量，无人共用。

其余三项各自绑着 **10–20 个与别处共用**的常量（`REF_*`／`VIEW_*`／`SHOT_*`），硬拆就得连带搬走共用常量——**那不是拆，是把别人的零件也拆走**。

**由此纠正我在 §八 的一句混话**：

> **分组是逻辑的，拆是物理的，两者判据不同。**
> - 分组按「**判据对象**」：引用／账务／产物／格式／回关——为了"能按组跑、能分头改"。
> - 拆按「**依赖闭包**」：一项的依赖是否**只属于它自己**——为了"能单独搬走"。
> **逻辑上同组的项，物理上未必能一起搬。**

**所以拆之前先算一次依赖归属**（本项目做法）：把每项用到的模块级常量列出来，按"只被本组用／也被别处用"两栏分。**只有第一栏为空的项才能整项搬走。**

**降耦才是下一步**：先把 `REF_*`／`VIEW_*`／`SHOT_*` 各自收进带前缀的命名区、确认没有跨组引用，再谈搬。

### 八·四 拆完的结果与方法（2026-11-17，49 项 → 入口 819 行 ＋ 七个模块）

| 模块 | 行数 | 装什么 |
|---|---|---|
| `_consist.py`（入口） | 819 | 注入 ＋ CHECKS 清单 ＋ 分组 ＋ 主流程 |
| `_core.py` | 25 | 注入点 |
| `huiguan` / `chanwu` / `shitu` | 131 / 619 / 86 | 回关／产物／视图 |
| `sheet` ＋ `sheet_vocab` | 855 / 31 | 镜表检查 ＋ 镜表词汇 |
| `geshi` / `yinyong` / `zhangwu` | 501 / 773 / 1006 | 格式／引用／账务 |

**三件带得走的东西**：

1. **先分组可执行，再物理拆**（§八·一）——`--group` ＋ 覆盖自检，比直接搬文件安全一个量级。
2. **拆的边界是词汇表，不是功能组**（§八·三）——`SHOT_*` 是镜表的语言、`REF_*` 是参考图的。共用常量多＝说的是别人的语言。
3. **判依赖用 `ast`，判"跑通"看 `Traceback`**——这两句是五批实战换来的，别再靠正则和退出码。

**三个必踩的坑**（都实测过）：

| 坑 | 现象 |
|---|---|
| 切函数带走夹在中间的常量 | 搬完 `NameError`：常量也是使用者，常量之间也会互相读 |
| 正则改到字符串里 | 消息字符串里的 `README` 被改成代码名，检查报「没有那个 README」 |
| `ast` 的 `col_offset` 是**字节**偏移 | 中文行按字符切，切出 `PTR_MANIFEST +_core.PTR_MANIFEST**——` |

**搬运器**：`templates/checks/_mvchecks.py`——闭包按 ast 算、按节点切、按字节改、同节点去重。**别手搬，手搬必踩前两坑。**
