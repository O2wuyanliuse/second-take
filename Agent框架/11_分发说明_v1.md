# 11 · 分发说明（这套东西怎么带走）

> **2026-11-01 定**（作者：「框架可独立分发」）。
> **层**：**通用层**——整份可搬给别的项目。它讲的就是「怎么把框架带走」：能带走的是怎么做事，不是这套脚本
> **一句话**：**能带走的是「怎么做事」，不是「这套脚本」。** 规范与方法可以直接搬；
> 脚本里有一半是给这个项目定制的，换项目要改，少数要重写。

## 一、分发包长这样（结构不能改）

```
<分发根>/
├── Agent框架/           ← 全部 md（规范、流程、标准）
│   └── README.md
└── 00_原著/
    └── _*.py            ← 只放脚本，**不要带正文、设定集、台账**
```

### 为什么 `00_原著/` 这个目录名必须保留

`00_原著/_*.py` 全部靠同一行定位项目根：

```python
HERE = os.path.dirname(os.path.abspath(__file__))
PROJ = os.path.dirname(HERE)          # 脚本父目录的父目录 = 项目根
```

所以脚本必须待在 `<项目根>/00_原著/` 里。**把它移到 `Agent框架/tools/` 之类的地方，
这些脚本全推错根目录**，而且 `_selftest.py` 的沙箱机制会一起失效——
它的做法正是「把检查器复制进临时项目、靠 `__file__` 自动重定向」，这个技巧成立的前提
就是上面那两行。

> **接包的人那台 AI，得先过三问**（2026-11-02 实测）：能读你的文件／能**常驻**写你指定的目录／
> 写一次要不要你点一次允许。**三问全过才叫能干活；前两问过、第三问不过，它是顾问**——能读、能讲、能陪你判断，
> 但装不进你指定的地方。带沙箱、逐次审批的客户端就是这个类型：装这套包要写七十多个文件，等于让人按七十次手印，
> **门槛没消失，只是从「会不会用」换成了「愿不愿意点几十次」**。这不是那些工具的问题，是用途不同：
> 它们的沙箱为「给你出文件」设计，这套东西要的是「改你的工程」。**按用途分，不按优劣分。**

**结论：保住这个相对位置，一行代码都不用改。** 目录名叫什么无所谓，脚本的父目录
必须是项目根下的第一层。

> **但分发包里的脚本数 = 本项目数 − 2 ＋ 1**（剔掉的是 `_hollow.py`／`_probe_a.py`，见下；
> 加回来的那一份是 `packaging/_dupcheck.py` 的副本，进包落在 `00_原著/_dupcheck.py`——
> 因为「文档整段重复」这条规矩写进了发包的清单，**判据得跟着人走**——规矩进了清单、尺子没进包，收包人就无法验证，所以把 `_dupcheck.py` 一并复制进包）。
> **具体数字不写在文档里**：它已经被写死两次、过期两次（第一次写 22 实际 20；
> 这轮加了 `_pname.py` 又该 21）。以 `_pack.py` 打出来的那行为准，
> 包内文档里的数字由打包时按实际计划现算填入，不靠手抄。
>
> `_hollow.py`（专名对账件）与 `_probe_a.py`（A 组探针）：两者都要**读正文与设定集**才有意义，
> 包里没有正文，它们本身就空转；而代码里嵌着整套世界词汇表——带出去等于**把设定集换个文件名送人**。
> **「工具」和「词汇表」要分开看。** 所以包内 `00_原著/` 的脚本数，比上面列的总数少 2。

## 二、三层清单：哪些能直接带走

### A. 直接带走，改都不用改

| 文件 | 说明 |
|---|---|
| `Agent框架/*.md` | 全部规范。里面的 `00_原著/xxx` 是**项目实例**，带走后不存在是正常的（见 §四） |
| `00_原著/_mkview.py` | **完全通用**：任意 md 表格 → 合规可填件。它不认识任何项目，读表头名不读列序号 |
| `00_原著/_loop.py` | **完全通用**（但依赖 `_consist` 与 `_anchor` 在场）：改完跑一条，重算时长 ＋ 扫引用一致性。**它自己不含任何项目常量**，只是把「改一处就要重算、就要复扫」这个动作缩成一行 |
| `00_原著/_gen_diff_view.py` | **完全通用**：任意两份同源文本 → 双栏对照 HTML。只吃两个文件名，不碰任何项目常量 |
| `00_原著/_style_check.py` | **完全通用**：任意图片 → 画风四组数值（唯一色数／前 12 色覆盖／饱和度／梯度分位与硬边占比／亮度）。**只回答「两张画像不像」，不回答「画得好不好」**；文件头写了四条局限，**核心一条：只能比同一个人、同景别类型的两件，跨角色比会得出反的结论** |
| `00_原著/_pname.py` | **完全通用**：项目名只认一处来源（环境变量 → README 的「项目：」标记 → 设定集文件名）。**其余脚本都 import 它**——名字散在多处就一定会漂，那是 2026-11-01 的实测：31 条规则曾有三个副本、编号完全一致却有 6 条暗中分叉|
| `templates/checks/` | **完全通用**：`_links`／`_orphan`／`_diff` 三支检查器（扫路径／扫孤儿／扫账实）＋ 拆分大脚本的两支工具 `_depmap`／`_mvchecks` ＋ 配置示例。**根目录用环境变量指**，不改代码就能换项目（用法见该目录 README）。 |
| `00_原著/_asset.py` | **半通用**：查「文档把某张图当成它不能干的用途」。判据来自一份台账 JSON（`can`／`cannot` 两个列表），**换项目要换台账，判据本身可复用**。关键一条经验：**距离要在同一个表格单元格内算**——首版按整行算，把「这张图 ｜ 能干什么 ｜ 不能干什么」这种复述表全报成了越界（7 处误报，全是归纳报告） |
| `00_原著/_orphan.py` | **半通用**：查「有没有 md 谁都没提」。它真正有用的模式是 `--only`（**这次新加的件有没有人提**）；全库模式只会列出几十份历史过程稿——**那是过程，不是问题**，所以全库模式永不判红 |
| `00_原著/_safeio.py` | **完全通用**：写文件时按原换行写回（读原文件 → 检测 CRLF／LF → 按原样铺开）。**它防的是一个不报错的错**：`io.open(p, "w")` 在 Windows 上会把 `\n` 写成 `\r\n`，于是「只改一行」在 diff 里变成整篇重写。本项目 2026-11-07 一天栽了三次。三条硬规矩：混合换行**不猜、直接拒写**；`edit()` 要求锚点恰好出现 `expect` 次，**不符就不动文件**（「替换 0 处然后照样 write」正是要把整篇重写的那个动作）；写回前先把正文里的裸 `\n` 统一成目标换行 |
| `00_原著/_state.py` | **完全通用**：生成开工入口卡 `STATE.md`（一页、≤34 行、跳转≤2）。**它不判断任何事**——只把四份源文件里已经写着的东西搬到一页上：当前件与判据从锚定表抽（`*锚定表*.md`，按列名语义取「第一个状态不是 ✅ 的对象」）、挂起状态从序列文件顶部横幅读、「上一轮停在哪」从通道最后一条 G 行取；抽不出来的只有两块（本阶段红线、需要作者拍的那句），在 `*手写区*.md` 里手写。卡里带源文件指纹，`--check` 比对——**源改了卡没重生成就是过期**。带 `--self` 反向测试、`--print` 只看不写 |
| `00_原著/_basis.py` | **完全通用**：扫锚定表与判据定义表，查三件事——① 判据里有没有拿生成图当参照；② 同一对象有没有并列基准；③ 判据有没有裸像素（px/cm/mm），只在景别固定时才允许。它不认任何项目专名：锚定表按文件名 `*锚定表*.md` 找，判据表按**表头语义**（「判据」「该看见」「通过标准」）找，不按列序号。带 `--self` 反向测试与 `--files` 覆盖自查 |
| `00_原著/_pname.py --check` | 同上的自查开关：扫 `00_原著/_*.py`，报出白名单外还写着项目名的行。2026-11-02 同一病根被外部实测抓了两轮（一轮六处、一轮两处），两次都靠人眼扫——这条命令就是那次「扫」的固定版|
| `00_原著/_dupcheck.py` | **完全通用**：同一段文字连贴两遍／整段重写伪装成小改动的检查器，可对任意目录跑。**源在 `packaging/_dupcheck.py`，打包时复制进包**——因为「文档整段重复」这条规矩写进了发包清单，判据得跟着人走；规矩进了清单、尺子没进包，收包人就无法自己验 |
| `_links.py` | **完全通用**：查本仓库里「反引号写出来的路径」到底在不在。跟 `_anchor.py` 分工——那个要项目台账当基线，这个不要：**只认本仓库的一级目录**，别的一律当「读者项目里该有的」，所以拿走就能跑。豁免表 `links_allow.txt` 随库各一份，每条必须写理由。**两遍**：① 带斜杠的路径；② `[类别]名字` 这种不带斜杠的引用有没有落点（**窄口径**，只认类别前缀——放开到所有裸名，实测 199 个候选里大半是模型名与标签，红了就变日常） |

| `_anchor.py` | 锚点判据建立在本项目的引用格式上 |
| `_diff.py` | 比对的是本项目的正文与账 |
| `_lint.py` | 扫的是本项目的作废词表 |
| `_world.py` | 绑定 `[世界]`／`[人物]` 两张具体表与它们的列 |
| `_layer_audit.py` | 专名来源 B 是本项目的专名台账。**但 `STRUCT` 那六条判据是通用的**，尤其「通道 G 号」：通用层不许出现（项目层整份跳过，中间档已取消）——换项目照抄正则即可，它查的是「有没有指到一份不随包走的台账」，与具体作品无关 |
| `_art.py`／`_frame.py`／`_probe_a.py`／`_hollow.py`／`_cost.py` | 绑定本项目的过程稿目录与字段 |
| `_view.py`／`_board.py` | 绑定本项目状态源的阶段与环节 |
| `_ch.py` | 查本项目那条 **1.4 MB** 的跟进通道：先生成「每条一行」的 tsv 索引，再按键取单条全文（`-f 编号`）、列还开着的（`-r`）。**换项目只改两行路径就能用**，但索引字段绑的是这条通道的列序 |
| `_ruler.py` | **写死了本项目三个人的身高与头身比**（三个数与区间都在项目层的锚定表里，通用层不复制）。换个项目就是一张空白网格，一个数都用不上 |

**这是实话：`00_原著/_*.py` 这一堆里，真正开箱即用的只有 2 个**（`_mkview` 与 `_gen_diff_view`）。
其余都绑着这个项目的表名、专名或目录结构。

> 但这不是失败。这套框架的价值从来不在「脚本能复用」，而在**「知道该设哪些卡口」**——
> 什么该查、查什么、什么时候报红，那些判断在 md 里，是能带走的部分。
> 脚本只是把判断落成程序的一次性实现；换项目时照着 md 重写一遍，比重构旧脚本快。

## 三、换一个新项目，最小起步是这四步

1. 建 `<新项目>/00_原著/`，把 `_mkview.py` 与 `_gen_diff_view.py` 放进去（这两个开箱可用）
2. 抄 `Agent框架/` 的 md。**不用全抄**，分两种：

   | 谁要它 | 文件 |
   |---|---|
   | **脚本要它**（少一份就跑不起来） | `状态源.json`（见第 4 步）／`环节表_文字到可视化_v1.md`／`10_可视化映射_v1.md`／`[台账]跟进通道.md` |
   | **人要它**（少了能跑，但读不懂） | `README.md`／`12_人话对照_v1.md`／`02_流程层_交接防错.md` |
   | **本项目专用，别抄** | `失败案例集_v1.md`（写的是本项目踩过的坑）／`体检_*.md`／`脱钩体检_*.md`；**跟进通道只建个空文件，别抄历史条目**（脚本只要它存在，用来页脚计数） |

   > **实测过（2026-11-01）**：新建一个只有「3 份 md ＋ 3 个脚本 ＋ 4 键状态源」的空项目，
   > `_where`／`_mkview`／`_gen_diff_view` 三个都直接跑通，视图正常生成。
   > 所以第 4 步那份骨架不是示意，是照抄能用的。
3. 按 `10_可视化映射_v1.md` 先定六类产物类型的映射——**这一步不做，后面的卡口都立不住**
4. 建 `状态源.json`（字段名可改，但 `_where.py` 要跟着改）。**最小值就这几个键**，先跑起来再长：

```json
{
  "更新": "2026-11-01 09:00",
  "环节": [
    {"id": "E0", "名": "对齐扫雷", "状态": "进行中", "备注": "做到哪了、下一步是什么"}
  ],
  "下一件事": ["第一件具体的事，动词开头，一句话"],
  "挂起": []
}
```

> `_where.py` 只读**这四个**：`更新`／`环节`（`id`、`名`、`状态`、`备注`）／`下一件事`／`挂起`。
> 本项目状态源里还有 `阶段`／`层级`／`断点`／`视图`／`最近`／`口径`——那些是给 `_view.py`、`_board.py`
> 用的，**新项目不建也能跑**。别照抄本项目的 600 行，那是它的实况，不是模板。

至于 `_gate`／`_consist` 那一批，**等新项目真的长出需要它们的病再建**。
先有规范，后有害处，再补检查器——反过来是先造锁再找门。

## 四、带走之后，那些「不存在」的东西

框架层有上百处提到 `00_原著/xxx`。它们分三类，**只有第三类会真的跑起来**：

| 形态 | 例子 | 在你这儿会怎样 |
|---|---|---|
| **名字**（已降级） | 「项目级改法见 `[项目]改法规则`」 | **不存在是正常的**。它说的是「你该有这么一份东西」，不是「我这儿有一份，你去打开」 |
| **产物路径** | 「落 `00_原著/视图/xxx.html`」 | 改成你项目的对应目录即可 |
| **命令** | `python 00_原著/_gate.py` | 脚本位置没变，直接就能跑 |

**为什么「名字」不带路径**：2026-11-01 改的。原先写成完整路径（带 `00_原著/` 前缀、带 `_v1` 这种版本后缀），作者指出——**通用层封包发给别人，别人照着点全是断链，会以为自己装错了。**
断链本身不弹报错（md 阅读器不校验链接），但它会让人**去追一个不存在的东西**，那比报错更磨人；而写这份说明的人很难替每一个读者逐处解释「这处是例子、那处是必需」。

所以规矩改成：**通用层里的项目件只留名字、不留位置。** 位置只在两种地方出现——`_原始归档/` 这类**目录约定**（你本来就该建），以及 `Agent框架/` 下**随包一起带走**的文件。

> ⚠ **反向边界：这一条只管「通用层提到项目件」。** 你自己项目内部互相引用时，恰恰相反——**必须写全**（从项目根起算、能解析到一个真实存在的文件）。只写文件名，等于写了一个只在你脑子里成立的路径，检查器会判断链，而你多半不知道为什么。
> 一句话分开：**自己项目里写全，往外发只留名字。** 详见 `Agent框架/02_流程层_交接防错.md` 四·补二十四（三）。

**真会跑的只有第三类**，数量不写死在这里（一写数就漂，`_consist` 每次现算并印在 `[scope]` 行里）。

**这条有机器守**：`_consist` 扫通用层，一旦又冒出「`00_原著/` ＋ 方括号件」这种带位置的引用就报——防的是「下次我又顺手写成完整路径」。

**别把两份当成对等的两边（2026-11-12 立）。**

骨架库不是「另一个独立版本」，它是**脱敏蒸馏过后的本机**。关系是单向的，不是双向对齐。

所以看差异时只问一件事：**这份东西能不能蒸馏干净？**

- **能蒸馏的**（形状、判据、流程、脚本）：骨架库那份该跟本机一致。不一致 = 该回流没回流。
- **不能蒸馏的**（项目名、真实词表、具体路径、真实案例）：骨架库那份**永远是另写的**，
  不一样才是对的。别拿它当缺口，也别提议「让骨架库追上来」——它从来不是追的一方。

反过来问「骨架库落后了要追上吗」，这个问法本身就错了：**本机是正本，骨架库是从它身上取下来的那一层。**
取不下来的是项目本身，不是漏掉的内容。
