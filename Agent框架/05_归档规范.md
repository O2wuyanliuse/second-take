# 05 · 归档规范（文件产物管理 · 长线项目专用）

> **路径说明**：本文出现的 00_原著 下具体文件名都是**项目实例**（示例、产物位置），带走后不存在是正常的；命令块里的脚本调用是**位置约定**，位置不变就能跑。详见 `11_分发说明_v1.md` §四。

> **读者**：AI
> **层**：**通用层**——整份可搬给别的项目。前缀、时间戳、分区、落盘——任何长线项目的产物管理都适用
> 定位：长线项目产物必然堆积，**归档制度必须从第一天就严格立好**，否则文件乱成一锅粥再收拾就晚了。
> 这是「统一门阀」原则在「文件产物」维度上的落地：命名、时间戳、归档分区、唯一真相源，四位一体。

---

## 一、核心原则（一句话）

**"原文"只有一个真相源；所有产物分门别类、前缀标性质、读取时自检时间戳；被淘汰的旧稿进归档，不删、不混。**

---

## 二、四类文件前缀（一眼分辨性质）

| 前缀 | 含义 | 例子（`<卷>` 是**占位符**，不是文件名，写文档时换成实际卷名） |
|---|---|---|
| `原文_` 或 归档原件 | 唯一工作真相源（只有一个） | `_原始归档/<卷>_原文原件.txt` |
| `[草稿]` | 未落盘的修改草稿 | `[草稿]<卷>_<主题>.md` |
| `[中间稿]` | 含待落盘改动、但非原文 | `[中间稿]<卷>_含N处待落盘改动.txt` |
| `[勘误]/[审校]/[标注]/[诊断]/[项目]` | 各环节产物 | `[勘误]<卷>_台账`（后缀同其他，一律 `.md`） |

---

## 三、读取时自检（时间戳交叉比对，防"搞错文件"）

每次读取文件用于工作前，**自检修改时间戳、交叉比对**：

- 以原文为基准 → 确认读的是 `原文_`/归档原件，时间戳 = 最后定稿时间，不是某份草稿；
- 用草稿 → 草稿时间戳必须**晚于**它所依据的原文，否则草稿已过期；
- 勘误/标注 → 对象必须是"已定稿的原文"，不是未落盘草稿；
- **在修改时间维度上，不符工作需要的文件一律不用，先问作者。**

### 时间戳自检的前缀免检表（先分类，再判过期）

> 来源：2026-10-27 填坑——"晚于原文"这条自检规则**只对「待落盘的活草稿」成立**；`[中间稿]` 等归档留存件"旧"是正常的，套同一条规则会误判过期。

**自检顺序铁律：先看前缀分类，再判时间戳**——不是"看时间、判过期"，是"先分类、再自检"。

| 前缀 | 是否参与"晚于原文"自检 | 说明 |
|---|---|---|
| `[草稿]` | ✅ 必须自检 | 待落盘的活稿，晚于依据原文才算没过期 |
| `[中间稿]` | ❌ 免检 | 污染后转正名留存的证据件，"旧"是正常的 |
| `[勘误]` / `[审校]` / `[标注]` / `[诊断]` / `[项目]` | ❌ 免检 | 是各环节的产物/记录，不是待落盘活稿 |
| `原文_` / 归档原件 | ❌ 免检（另有校验） | 走 md5 比对，不套"晚于"规则 |

### 分层自检（日常轻、关键重，防臃肿）

> 防错不是机制越多越安全，是"该轻的轻、该重的重、各在其位"。

- **日常自检**：看 `_原始归档/版本说明.md` 里的"内容版本 + 内容定稿时间"（人可读，一眼看清），不看文件复制时间戳。
- **关键落盘前**：跑 `md5sum` 与版本说明表比对，一致才落盘（机器兜底，只在关键时刻跑）。
- **判断"草稿是否过期"**：草稿写的时间须晚于"它所依据原文的**内容定稿时间**"，不是晚于"归档复制时间"（归档会刷新文件时间戳，但内容没变）。

---

## 四、归档分区（`_原始归档/` 与 `99_过程稿`）

- **`00_原著/_原始归档/`**：只放**干净原件**（md5 校验过、永不动）。这是唯一真相源。
- **`99_过程稿/`**：放**被新框架吸收的旧文件、被淘汰的中间产物**，防污染。
- **铁则**：原始原文必须复制原件、在 `_原始归档/` 单独归档，绝不裸奔；被淘汰的文件进 `99_过程稿`，不删。
- **归档不改内容**：归档动作 = 复制，不得改内容；`_原始归档/` 里的文件内容一经归档，永不动。

---

## 五、落盘规则

- 落盘 = 把"已定稿的草稿"合入"原文"，草稿随之归档进 `99_过程稿`。
- **落盘前，原文必有回退锚点兜底**（见 `02_流程层` 环节0备份纪律）。
- 落盘后，中间稿/草稿若已被完整覆盖，再判是否删（作者回收站权限在作者手上）。

---

## 六、为什么"删"要谨慎

- 中间稿、旧稿里可能有**已被认可、但还没合成的成果**（如 22 处待落盘改动）。
- **先归档、后判断**：判断"是否已被完整覆盖"之后，再决定删不删；判断不清就不删。
- 回收站的清空权限在作者手上，AI 不擅自删除任何可能含成果的文件。

---

## 七、交接档自身的时效性（最后的口子，必须堵）

> 来源：2026-10-27 复盘发现——交接档只做指针、但指针会过期；若交接档自己不带时间戳、又不被自检，会重蹈"读旧状态当事实"的覆辙。

**铁律一**：交接档**必须带"收工时间戳"**（精确到时分，如 `2026-10-27 13:24 收工版`），每次收工更新。

**铁律二**：开工读交接档时，**先自检交接档的时间戳**，判断"这份是不是最新的"：
- 不是最新（或存疑）→ 先找更新的 memory（agent 工作日志目录，如 `~/.<agent>/memory/` 里日期更新的日志）；
- 确认是最新，才以交接档的状态为准往下走。

**铁律三**：交接档的"未完成事项"状态，一旦有变化（确认/落盘/推进），**必须当场更新交接档**，不能只记在 memory 里等收工。

---

## 八、json → md 搬家：裸文件名一定会现形（2026-11-01 立，一天内发生三次）

> **现象**：`状态源.json` 的「最近」超过 8 条时，最老的一条要搬进 `99_过程稿/状态源归档_最近.md`。
> 每次搬完，`_anchor` 都会报一处「路径不存在」，而那段文字在 json 里**一直是好的**。
>
> **原因**：`_anchor` 只扫 md，不扫 json。json 里的裸文件名（只写名字、不写目录）一直是免检区。
> 一搬进 md，它就暴露了。**三次都是同一个原因**（索引层标准、出图参数追溯、设定集口径补丁）。

**搬之前先预扫，一条命令**（在项目根跑）：

```bash
python -c 'import io,re;t=io.open("99_过程稿/状态源归档_最近.md",encoding="utf-8").read();print([m for m in re.findall(r"`([^`]+\.(?:md|txt|json|html|png|jpg|mp4))`",t) if "/" not in m])'
```

它列出**所有带文件后缀、但没有目录前缀**的引用。逐条判断：

- 真的在指某个文件 → 补全成相对项目根的路径；
- 只是句子里提到这个名字（不是引用）→ 换成不带后缀的写法，别让机器把它当路径。

**但最终判据不是这条命令，是 `_anchor`。** 搬完立刻跑 `python 00_原著/_anchor.py`，它报一处就补一处——
预扫只是让你少来回一趟，权威始终是那个每天在跑的检查器。

> 为什么值得单列一条：这三次的成本都不是「修一个路径」，是**每次卡住一次提交**。
> 更贵的是它很隐蔽——搬进去的文字读起来完全正常，只有机器知道那条路径不存在。
