## 〇、为什么要有这份表（病根，先讲清）

`00 人机接口层` 的判据是：

> 「凡**需要人逐条核对／裁决**的产出，必须给视图。」

这句话判的是「**要不要人看**」——一个**语义判断**。语义判断只能由 AI 在现场推一次，推完散在对话里，**不落盘**。后果是换一个人来，AI 照样推得动「这里挺多的，给个表吧」，**但它不知道这一步叫什么、有几步、彼此什么关系**，所以推不出"这里该给视图"，只能推"这里给个表格凑合"。

**换人不失效的，是「人的眼睛要视图」。失效的，是「在哪一步给」。**

所以本表只做一件事：**把触发点从「AI 判断」搬到「产物类型」上。** 类型是客观的，换谁走这条路过都一样。

**三条不变量**（改了这三条，本表就废）：

1. **类型挂在产物上，不挂在环节上。** 同一环节换了产物类型，形态跟着换。
2. **映射唯一，不许临场发明。** 表里没有的类型，先回这里加，不许就地设计。
3. **"要不要"这个问题不存在。** 走到标了类型的产物，直接产出；不产出＝这一步没走完。

## 一、六种产物类型

| 类型 | 判据（问一句就能定） | 典型产物 |
|---|---|---|
| **T1 · 逐条裁定型** | 是不是**一条一条**过，每条都要一个态度？ | 问题清单、扫雷清单、判据表、核对清单 |
| **T2 · 二元拍板型** | 是不是每条只要**二选一 ＋ 一句补充**？ | 设定拍板、单格调度、待裁冲突 |
| **T3 · 状态水位型** | 用户会不会**回头看第二遍**？ | 进度板、位置图、谁卡谁 |
| **T4 · 整段搬运型** | 是不是**原样拿走**、一个字符都不能改？ | 提示词、可复制的正文段 |
| **T5 · 图像产物型** | 产物**本身是图**，文字只是它的注释？ | 三视图、基准帧、首帧 |
| **T6 · 台账登记型** | 是不是**一行字**记完，没有可裁的东西？ | 投喂登记、询问记录 |

> **T1 与 T2 的界线**：T1 每条可以有 2–4 个选项 ＋ 长补充；T2 每条只有一个开关 ＋ 一行说明。
>
> **分错不是"不要紧"——2026-11-01 被真数据打了一次脸**：E0·7 的待裁冲突原标 T2，而实测四条里有一条需要四选一。标成 T2，等于把人逼进「做／不做」，正解「只补影响分镜的」当场消失。
> **判断方法只有一句**：问「这条是不是只有两个合理答案」。**答不上来，就是 T1。**

## 二、类型 → 形态（唯一映射）

| 类型 | 形态 | 载体 | 不许怎样 |

## 四、T4 的两条特别规定（作者 2026-11-01 提出，原规范没覆盖）

### 4.1 分割符：怎么标范围又不违反 L4

**问题**：提示词是要整段粘进生成平台的。多选一行参数、少选一段描述，都是一次生成的钱。现有那份**提示词交付格式**规范只规定"框在外面"，**没解决"从哪到哪"**。

**解法按载体分两路**：

**（a）对话内交付**——围栏块前后各一行灰字，**这两行在块外，永远不会被选中**：

```
↓ 下面这一整块，从头到尾全选（共 N 段，中间的空行也是正文）

（提示词，一个围栏块，块内只有提示词）

↑ 到此为止。参数行在上面，不用一起复制。
```

**（b）HTML 交付（推荐）**——`<pre>` ＋ 右上角**一键复制按钮**，旁边显示**字符数**。
复制按钮取 `textContent`，**不带任何装饰**。作者粘完拿字符数对一眼就知道有没有漏。

> **为什么 (b) 更根治**：L1.2 当初把"用户→AI 的转录"删掉了，但"选中→粘贴"这一环还在。**点一下比拖选一次可靠**，因为拖选会漏，点不会。
> **为什么这不违反 L4**：L4 禁的是"用框线**包**内容"——框线会被一起选中。按钮和字符数是**功能**，在内容外面，且不进选区。

### 4.2 参数行必须与提示词块分开

参数行（画幅／时长／尺寸）**单独一行，放在块外**。它是要填进平台参数栏的，混进提示词等于给模型读了一行无意义文字。

## 五、卡口怎么落地（不许只写在纸上）

**这张表自己也是纸。** 让它变成闸，需要两件事：

| 要做的事 | 落在哪 | 状态 |
|---|---|---|
| **生成器**：md 清单 → 合规 T1／T2 件 | `tools/_mkview.py` | **✅ 2026-11-01 已做并实测**。五项硬要求内建；反向测试（删掉 `id="badge"`）→ `_consist` 当场报红，证明不是假绿。**含「裁决」列的清单会生成「已裁」只读行**（无控件、绿框标结论），全裁完自动收起解锁与复制——**裁完的件不该还能改，那会让人以为判决可以随手推翻** |
| **第二生成器**：镜表 → 环节视图（总表／分派／单格） | `tools/_mkview_flow.py` | **✅ 2026-11-12 已做并实测**（23 格真表跑通）。分工写死在脚本头：**清单问「你选哪个」，镜表问「这格对不对」**——别用一个脚本干两件，那会让两边都变成参数堆。**它不判合格**，只摆参数，页签里没有「结论」 |
| **探针**：有清单没视图 ／ 视图指纹过期 → 报红 | `_consist.py`「清单↔视图配对」 | **✅ 2026-11-01 已做**。判据用**内容指纹**不用 mtime（checkout 后 mtime 全是检出时间，比了等于没比）；反向测试＋元测试都抓得住 |
| **统计自证**：本表的统计行 vs 表格实际行数 | `_consist.py`「映射统计」 | **✅ 2026-11-01 已做**。逐行数 🔒／◻／—，与统计行对不上就报红；「几件」这类推导值算不出来，`[scope]` 里写明不核 |

**生成器怎么用**（三行就够，不用记参数）：

```
python tools/_mkview.py 你的清单 -o "[视图]XXX.html"
# 默认按各条「选项」列走，缺省用 t1＝采纳／覆盖／作废
# 二元拍板加 --mode t2（已定／未定）；不要两阶段加 --no-stage
```

**输入只要一张 md 表格，表头必须有「问题」或「条目」列**，其余列（依据／选项／建议／编号）都可缺。
样板见 `[示例]清单输入样本.md`（那是**项目层**的示例件，包里没有）；结构就是三列——条目／依据／处置。产出物是一张能直接点的视图。

> **它内建了什么**（照 L1.2 五条，不用再逐份核）：两阶段只读→解锁、复位基线取 `defaultChecked`／`defaultValue`、`DOMContentLoaded`／`load`／`pageshow` 三处归位、`id="badge"` 三态徽标、回执裸文本、必答校验（缺几条点名几条）、不写 Storage。

**第二生成器怎么用**（镜表 → 环节视图）：

```
python tools/_mkview_flow.py 你的镜表 -o "[视图]环节.html"
python tools/_mkview_flow.py 你的镜表 -o out.html --pick T-04   # 单格页默认开哪格
python tools/_mkview_flow.py 你的镜表 --emit outputs/01_导演表    # 逐格落盘 <格号>.json
```

加 `--emit <目录>` 就**逐格落盘**，一格一份 `<格号>.json`，下面是这一格的全部参数。

> **落盘件分五组**：身份（`shot_id`／`order`／`source`）／拍什么（`brief`）／怎么拍（`shot`）／素材（`material`）／参考（`camera`），外加 `meta`。
> **17 栏全进，一栏不留。** 少放一栏，将来生成视图就得回读 md——一份数据两个源，正是现在 xlsx 要配个预览 html 的原因。
>
> 三个设计点，改之前先看：
>
> ① **`desc` 是派生的，不是源字段。** 取「本格唯一信息」，缺了才回落到「镜头方案」前 40 字，`desc_from` 记着它从哪来。
> 手感件里有独立的 `desc` 输入框，那是样机——真件**不许**让人单独填它，否则两个来源会漂（回执第四条已定）。
>
> ② **`camera.ref: true` 是硬标记。** 落盘之后 `〔参〕` 那个括号没了，下游读的人看不出它是参考值。
> 靠文档提醒不可靠，**把一个布尔字段写死**才可靠。它为真时：不进提示词、不作合格判定。
>
> ③ **区间值不拆。** `距 5.0→2.5` 是「起止两个机位」，压成一个数比空着更坏——
> 所以 `distance`／`height` 留 `null`，`raw` 永远原样保留，要读就读 `raw`。

三个页签：**总表**（一行一格，横向扫一眼看出哪格不对劲）／**分派**（「本格唯一信息」×「资产」——要说的事有没有主人）／**单格**（选一格，全参数摊开，含它没认出来的列）。

> **一个必须写下来的硬事实（2026-11-12 实测）**：试行手感件上有**四个**页签，但**只有三个能从镜表生成**。
> 第一页「E0·6 对齐扫雷」的输入是**清单**（问题／依据／选项），不是镜表——那一页归 `_mkview.py`，不归这个。
> **「脚本读镜表生成四页」这句话是错的**，别照它排期：按它做，第一页永远是编的。

> **认表比取值更容易出事**：脚本要同时看到「格」列 ＋ 至少两个强特征列（景别／镜头方案／呈现／节奏／资产／动不动／变化）才认。
> 只按「格」判的话，镜表旁边那张「必须传达的信息 ｜ 主格 ｜ 谁来兜」的映射表会被当成镜表——
> **23 格变 46 格，而且一句错都不报**（2026-11-12 本地实测踩到，改完才归位）。

**探针的边界，必须写明——它不比它看起来更有用：**

| 情况 | 守得住吗 |
|---|---|
| 有清单、没视图 | ✅ 报「没有配对的视图」 |
| 清单改了、视图没重生成 | ✅ 报「已过期」，附指纹对比与重生成命令 |
| 视图是手写的、没留指纹 | ✅ 报「没法判断是否过期」 |
| **一个清单都没有** | ⚠ 只报「没有可对的」——**不许当绿**，但也不红 |
| **该写清单却压根没写** | ❌ **守不住** |

最后一行是它的天花板：**框架不知道你走到哪一步了。** 进度在人脑子里、在交接档里、在 `状态源.json` 里——而状态源实测落后半日。所以「E0·6 该出视图、结果给了文字堆」这件事，机器仍然发现不了。

**这一格空着不是漏做，是做不到。写在这里，免得下次有人以为它全守住了。**

## 六、这份表管不了的（边界，防越界）

1. **不管视图好不好看**——那是设计，表只规定形态的存在与结构。
2. **不管内容对不对**——T1 里那一条该不该裁、裁得对不对，归环节本身的判据。
3. **不管 E7 的提示词写得对不对**——那是 `07_视觉提示词规则`。
4. **不管"这个用户想不想要视图"**——L1 允许换载体（HTML／md／纯文字），但**"要给"不可取消**。载体可配，存在不可配。
5. **不管 T6**——台账一行，没有视图可给，别硬造。
