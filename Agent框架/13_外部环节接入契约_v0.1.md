# 外部环节接入契约 v0.1

> **这份文件管什么**：别人做的工具／技能，能不能替掉我们某一环；替了之后，纪律怎么不掉。
> **层**：**项目层**——**不进分发包**。文件自己写着「这套接入口是给本项目用的，不是通用协议」——接入口绑着本项目的环节与脚本
> **不管什么**：开源。整个项目目录**零开源**，见 `版权与开源红线.md`。这里说的"接进来"是**在你的机器上、你这一份工作里**接，不是分发出去。
>
> **状态**：🟡 **半可判·未验**。一次真实接入都没发生过，下面是从现有结构推出来的，不是试出来的。
> **第一例接入完成时，本文件必然要改**——改完才升到 v1.0。现在写它，是因为**边界要先划，否则第一例接入就会用"顺手"的方式落地，然后把边界挤变形**。

## 〇、先把定位摆正：我们卖的不是流程，是卡口

这个判断不是自谦，是查证过的：

- GitHub 上同类已经很成熟（`drama-skills` 3.4k star／`huobao-drama` 16.2k star），11 个 skill 的链路比我们完整
- 就在今天看的那个编剧 SKILL 里，人家的三层架构、版本号+待确认、元信息与依据、可跳过要登记、台账——**十二处和我们同构**
- 而那些"某一环做得特别强"的专用技能，只会越来越多，不会更少

**所以流程层我们没有优势，也不该在这儿卷。**

真正只有我们有的一样东西，用一句话说完：

> **他的纪律是写给执行者自觉遵守的，我们的纪律是写成脚本、会自己喊的。**

他写「未授权需改写，分别记录原文」——谁核？AI 自己。
我们同一句话后面站着 `_diff`。

这件事决定了接入口该怎么设计，也决定了 §二 那套分层。

### 〇·补 · 但光有卡口不够——还得「浅入深出」（2026-11-03 作者定）

**卡口解决的是「凭什么信」，「浅入深出」解决的是「凭什么选」。** 两个问题不一样。

同类产品越多，用户越不可能为了「更严」来选你——**严是负担，不是卖点**，除非他先信这件事值得严。

| | 做什么 |
|---|---|
| **入口浅** | 不用懂术语、不用先学流程、不用读完文档就能开始 |
| **过程深** | 每一环都在教：`E0`–`E1` 教怎么把剧本磨到能对齐；`E2` 之后**顺手**教景别、机位、运动、资产这些事 |
| **出口硬** | 交得出「能判的东西」才算过 |

**「顺便教」不是附赠品，是产品的一部分。** 用户做完一遍，会的东西应该比开始时多——否则他凭什么用这个，而不是那个「一键出片」的？

> **两个代价，都认了。**
>
> ① **调试阶段更累。** 八档景别、五种呈现方式、四件套、尺度锚——单看每一条都能砍。**但它们合起来就是「专业」与「业余」的分界线**，也是这个产品唯一能被选择的地方。
>
> ② **真想无脑一键出片的人会流失。** 拦不住，也不该拦——拦回来的用户会变成「用了但一直不满」，比流失更贵。介绍时讲清楚即可。

### 「浅」的具体做法：术语／人话／图，三样并排

用户看不懂「中近景」怎么办？**不是把它删掉，是给它配翻译。**

- **术语**：老手一眼认出 `MCU`，知道这边没偷工减料
- **人话**：「胸口以上，表情和手势都能读」
- **图**：一张扇形，他自己看

**三样并排，谁也不迁就谁。** 填表器就是这么做的（七档景别，每档配人话＋示意图）——**它在这个位置上不是分类工具，是教具**：逼用户七选一、每选一次看一眼解释，七次就记住了。

> **自造简化版是双输。** 新人学不到行业语汇，等某天在别处见到会想「原来这儿一直少东西」；老手看到档位不全，不会来纠正你，只会在心里记一笔「不太专业」。**两种损失都不当场暴露，都攒着兑现。**
>
> 所以：**有行业通用语汇的地方，不自造简化版。** 只在确实没有通用说法的地方（比如呈现方式里的「遮挡」）才自己定，并且定完要解释。

## 一、能替换的，和不能替换的

| 环节 | 能不能换 | 为什么 |
|---|---|---|
| **E0** 设定链（`E0·1`–`E0·7`） | ❌ **不能** | 产物就是真相源本身 |
| **E1** 裁决改写 | ❌ **不能** | 直接改正文，没有上游可对 |
| **E2** 分镜标注（含 `E2-0`／`E2-1`／`E2-2`） | ✅ 可以 | 产物是中间件，能对着原文核 |
| **E3** 导演表 | ✅ 可以 | 对着分镜核 |
| **E4** 角色锚点 | ✅ 可以 | 对着三视图六项核 |
| **E5** 场景基准 | ✅ 可以 | 对着美术定调核 |
| **E6** 首帧 | ✅ 可以 | 对着锚点＋契约核 |
| **E7** 提示词 | ✅ 可以 | 对着 31 条规则核 |
| **E8** 成片 | ✅ 可以 | 对着输出规格核 |

**为什么 `E0`／`E1` 不能换，不是因为地盘。**

这两环的产物**就是真相源**。外部交来一份设定、一份改写，**它没有"上游"可以对着验**——判断"这段改写对不对"要全卷上下文，机器给不出，人也只能逐句读。

而 `E2` 以后全是中间件：分镜表对上原文句、首帧对上锚点图、提示词对上 31 条规则。**它们每一份都有明确的"该对着谁"**。

> **一句话规则**：**能被验证的环节才允许外包，验证不了的必须自己做。**
> 这条规则不是偏爱，是能力边界。

## 二、判据分三层（这是「低门槛 × 严纪律」唯一能合起来的解法）

先摆一个不好看的数字，从 `放行表_可视化环节_v1.md` §一 末尾抄来的：

> 41 项检查里，**真正有脚本在跑的只有 8 项**。
> 标 ✅ 的那 18 项说的是「**判得了**」，不是「**已经在判**」。

这句话堵死了一条路：**我们不能要求外部环节过 41 项**——其中 23 项连我们自己都还没实现。拿没实现的判据去要求别人，是把我们的欠账转嫁给接入方。

所以只能分层：

### L0 · 硬闸（不接受豁免，机器核）

这四条跟「你干得好不好」无关，只跟「**你弄坏没弄坏**」有关。

| 项 | 脚本 | 拦什么 | 退出码 |
|---|---|---|---|
| 正文改动必须登记 | `_diff` | 改了原文／账，没写进台账 | 1 |
| 引用必须能回原文核 | `_anchor` | 引了不存在的文件、或原文里没有的话 | 1 |
| 红线不被破 | `_redline` | 开源动作、多出 LICENSE、凭据落文件 | 1 |
| 层级纯度 | `_layer_audit` | 通用层写了项目专名 | 1 |

**为什么这四条不能豁免**：它们不是质量标准，是**协作前提**。任何一条被破，后面所有人的判断都建立在假数据上——**假数据比没有数据更糟，因为你还会用它做决定。**

### L1 · 项目口径（给四张表，照对即可）

| 项 | 脚本 | 接入方需要的东西 |
|---|---|---|
| 作废词 | `_lint` | 作废词表（**58 条**，每条写明「旧话→现话」） |
| 常量 | `_const` | 常量台账（画幅／尺寸／头身比／人数） |
| 专名 | `_collab` | 专名表（本项目专名，不许自创变体） |
| 索引层 | `_world` | 锚点格式（`文件:行号` §片段） |

**注意这一层的形状**：接入方要的是**四张表**，不是四个脚本。

他不会读、也不需要读 `_lint.py` 那 300 行。他只要拿到「这 58 个说法是作废的」这张清单，自己避开就行。

> **这一层是"低门槛"的关键**——把"读代码"换成"对清单"。这也正是 `11_分发说明_v1.md` §二 C 类那段真话的用处：那 18 个脚本绑着本项目的表名和专名，**换项目基本等于重写**，所以别指望别人复用脚本；能复用的是**判据清单**。

### L2 · 环节自检（自带，只需声明）

外部技能自己那套判据——比如出图环节的视觉判据、剪辑环节的衔接判据。

**要求只有一条**：**写下来，能复现。**

不许出现「看着像」「感觉对」「自然一点」。这跟 `待打磨区` #11 那条是同一个道理：**判据能测的，别让人去看。** 判不了的，就明确写「这一项靠人眼，判法是 X」。

## 三、为什么这两件事能合起来（机制，不是口号）

「低门槛」和「严纪律」在常规做法里是**互斥**的：

- 严纪律 → 要求执行者遵守规则 → 规则越多，门槛越高
- 低门槛 → 不给约束 → 谁都能用，但质量靠运气

**我们能合起来，靠的是一个位置的移动**：

> **纪律不压在「执行者」身上，压在「产出物」上。**

| | 常规做法 | 本框架的做法 |
|---|---|---|
| 纪律写在 | 流程里（你要先做 A 再做 B） | 产物上（你交的东西必须 X 成立） |
| 谁来核 | 执行者自觉 | 脚本 |
| 换人之后 | 换个人就松了 | **不松，因为脚本不看是谁做的** |
| 接入方要懂什么 | 整套流程 | **只要知道产出物要满足哪几条** |

这就是为什么 `_diff` 比「在 `AGENTS` 那类全局规则文件里写一句要求」强——**它不看你怎么做，只看你做出来的东西对不对。**

一个 outsider 完全可以不懂我们的流程、不认同我们的方法、用一套完全不同的工具，只要他交出来的文件过得了 L0／L1，**它就是接上了**。

**这就是"低门槛"的全部含义：不是降低标准，是不要求对方改变工作方式。**

## 四、三种接入形态

| 形态 | 侵入度 | 要登记吗 | 要过什么 | 典型例子 |
|---|---|---|---|---|
| **A · 旁挂工具** | 零 | **不用** | 什么都不用 | 一个更好用的提示词生成器，人拿着用，产出自己贴回来 |
| **B · 环节替身** | 中 | **要** | L0 ＋ L1 ＋ 声明 L2 | 用别人的技能出 `E5` 场景基准图 |
| **C · 深度替换** | 高 | — | **不支持** | 替 `E0`／`E1`（见 §一） |

**A 形态刻意不设门槛**，理由是它**不产出交付物**——错了人当场就看见了，不需要机器兜。这是最轻的入口，也是"接受他人"最实在的落点。

## 五、B 形态的登记表（填一次，六格）

放在 `99_过程稿/接入登记/` 下，一个来源一份文件。模板：

```
# 接入登记 · <技能/工具名>

| 字段 | 内容 |
|---|---|
| 接哪一环 | E__（只准填 §一 表里标 ✅ 的） |
| 吃进什么 | 上游哪个文件、哪几段（写路径，不写"相关材料"） |
| **吃进的目录会不会被门禁扫** | 只准填「**会**」或「**不会**」。<br>**填「会」** → 必须同时给出处理方式（登记 `SKIP_REL` 带理由注释／改落点／其他），见 §六-6。<br>**填「不会」** → **也要写一句判据**（凭什么断定它不在扫描范围内）。这一格零成本、无人核，最容易被随手填掉，而它正好是埋假红的那一格。<br>**空着** = 把一颗假红埋进门禁里 |
| 吐出什么 | 文件名 + 格式 + **落在哪个目录**（最难的一条，见 §六-5） |
| 自报判据 | 它怎么判断自己这一环做好了（L2；写不出来的，就是没有判据） |
| 已验证 | 跑过几例、结果如何。**没跑过的写「未验」，不许写「应该没问题」** |
```

最后一行不是形式。`09_E4到E6_首帧组装契约_v0.1.md` §〇 立过这个规矩：**没有实例的契约是空想**。这份登记表同理——**没跑过的接入，登记了也只是意向。**

## 六、六个必踩的坑（前四条 11-03 在 skill 里实测；第 6 条 11-06 在 `03` 接入时实测；第 5 条仍是推演）

| # | 坑 | 实测证据 |
|---|---|---|
| 1 | **画幅／尺寸写旧值** | 今天把 skill 纳入版本控制时，在 `ai-video-pipeline` 里抓到 **6 处 `9:16`**，项目早已改 16:9（2026-10-30）。其中 5 处是真的过时参数，1 处是形态定义（该留，进了常量台账豁免） |
| 2 | **引用格式按自己目录算** | 同一个 skill 里 **21 处断链**全是假警报——它用相对自身目录的路径，`_anchor` 按项目根解析必然找不到 |
| 3 | **「」的语义不同** | 项目文档里「」＝**引用原文**；skill 里「」＝**举例／强调**。实测因此误判 1 处「锚点失实」 |
| 4 | **项目外路径写成项目内形态** | 我自己踩的：在通道里写裸文件名，`_anchor` 当项目内相对路径判「路径不存在」，两处阻断 |
| 5 | **产出物放错位置 → 脚本找不到 → 静默通过** | ⚠ **这一条最危险，且还没实测**（还没人接过）。 |
| 6 | **输入件落进被扫目录 → 假红**（第 5 条的孪生，方向相反） | ✅ **已实测 2026-11-06**：台卡回执落 `00_投喂/台卡回执/`，`_anchor` 把全库 md 当引用源扫，回执里逐条引原文 → **失实 1／行号 2**。加 `SKIP_REL` 两行（带理由注释、原件备份 `_anchor.py.bak-20261106`）后，门禁回 **12 项 · 绿 11／提示 1／阻断 0**，与接入前一字不差 |

**第 5 条单独说**，因为它是「零覆盖假绿」的接入版：

如果外部技能把 `E5` 场景图吐到 `99_过程稿/` 而不是约定的 E5 目录，会发生什么？——**没有任何脚本会报错**。画幅检查扫不到文件，就不检查；`_consist` 数不到，就当不存在。

**结果就是：图出了、看着挺好、门禁全绿、其实一张都没被验过。**

> **处置**：B 形态接入时，**必须有一项「产物存在性检查」**——它是这一环的验收触发器。
> 没有它，其余判据全是摆设。这条写进 §五 登记表的「吐出什么」那一格，**必须精确到目录**。

**第 6 条单独说，因为它和第 5 条是同一件事的两面：**

第 5 条是**产物落错位置 → 假绿**（该验的没验，片子看着挺好）；
第 6 条是**输入件落进被扫目录 → 假红**（没问题的被报错，人被迫去改门禁）。

方向相反，**同一个根因**：接入时没人登记「这个目录会不会进扫描范围」。

假红比假绿轻，但它烧的是**信任**：一份回执进来就红一次，红到第三次，人就开始习惯性忽略红灯——而那正是「红没有去向」的开端，也是这份协议里最贵的一种失败。

> **处置**：吃进的目录**必须**在 §五 登记表里声明「会不会被门禁扫」。填「会」的，三个选项选一个写下来：
> ① 把该目录登记进 `_anchor.py` 的 `SKIP_REL`，**必须带理由注释**（不带注释，下一个人不知道为什么要排除，也不敢删）；改之前备份原件（`_anchor.py.bak-YYYYMMDD`），改完复跑门禁，确认回到接入前的项数与分布；
> ② 改落点，把输入件移到扫描范围之外；
> ③ 让输入件不携带原文引用——做不到就别选这条。
> **不许「先红了再说」**：红过三次，这道闸就废了。

**一条实测出来的反向教训（同一次接入里）**：排除项加对了，理由却可能写错。那次注释里写着「回执里有一句在源里只有转述」——回原文核，那句「**为表诚意我教会在其中预存三成的定金**」**逐字有原文**；错在只搜了 `.md`、没打开 `.txt` 定稿。**排除的理由必须是「这类文件不是引用源」，不能是「它引错了」**——后者一旦成立，该改的是产物，不是排除表。

### §六-5 的机器判法：`out_policy: inplace` ＋ `touches`（2026-11-06 立，已实现并实测）

`step.json` 显式列出这一步只许改哪些文件：**相对项目根、分隔符统一 `/`、支持 `*` 通配**（交接件是 `v<N>` 变的）。

判据是「**改动集合 ⊆ `touches`**」，由 `run_step` 在调 check **前后各扫一次项目**得出，**不看 check 自报**。

- **声明的文件一个都不存在 → 配置错误（2）**：先把「声明本身立不立得住」查掉，否则名字拼错时，越界判定会永远绿。
- **本次运行改动 0 个文件 → 合法**（check 只读时就是这样），打「0 个：check 只读」。**不许为了「让检查有东西可看」加假写入。**
- **`touches` 条目不许写成 `*` 或 `**`，也不许覆盖到项目根**——那等于 `allowed_roots` 换个名字，洞会原样回来。每个条目**至少带一个非通配的字面段**；空条目、绝对路径、含 `..` 一并驳回（配置错误 2）。**这三条在入口挡，不靠文档自觉。**

**它的边界（实测，不是推演）**：只覆盖**运行期间**的改动。跑之前改了什么，机器判不了——以交接件上一版的 mtime 起扫，**147 个文件都在变动里**（01／03 的产物、昨天出的图、临时脚本、台账、交接新版、门禁脚本本身）。拿它判收工环节，每轮必误红。**那一半由该环节 prompt 里的声明与台账条目留痕负责。不要把这条当成「改了什么」的全覆盖。**

## 七、这份协议管不了的（诚实列）

## 八、什么时候升到 v1.0

三个条件，缺一不升：

1. 有**至少一例** B 形态接入跑完全程（L0／L1 全过、产物进了正确目录、被脚本真的认出并检查过），**且接入方不是本项目开发者**——自己接自己属自证，不算
2. §六-5 那个「产物存在性检查」**每次接入都会自动跑、失败即变红**，不是一次性临时脚本<br>（2026-11-06 核查：骨架侧 `missing_outputs()` **只有定义、无调用点**，是死代码。**拿死代码凑这一条，就是 C7「名字带基准就当基准」的同型动作**）
3. 那一例接入**改动了本文件的至少一条**

第 3 条不是凑数。`09` 契约 §〇 那个判断在这里同样成立：**一份接入协议如果第一例真实接入之后一字未改，说明它当初是空想蒙对的，或者接入方为了适配它而扭曲了工作方式**——两种都不是好事。
