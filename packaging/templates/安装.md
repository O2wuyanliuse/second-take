### 1.1 `python --version` 失败时，先分辨三种情况，别一律叫人重装

命令无输出、退出码 1，**不等于没装**。跑这一句定位置：

```
python -c "import sys; print(sys.executable)"
```

| 打印出来的路径长什么样 | 是什么 | 你怎么做 |
|---|---|---|
| **什么也没打出来**（连这一句都 `CommandNotFound`／exit 9009） | **命令本身跑不动**——上面三行哪一行都对不上，因为它们都假设「至少能打印点什么」 | 这一行是 2026-11-02 一次实测补的：那位 agent 的机器上 `python --version` 和这一句**同样报 CommandNotFound**，于是文档在这格断掉了，它自己绕的。你做的是：Windows `Get-Command python`／macOS、Linux `which python`，拿到真路径再回头套上面三行（商店占位符／装了不在 PATH） |
| `/usr/...`、`/root/...`、`/workspace/...` 这类 **Linux 路径** | **你在自己的沙箱／容器里，不在他电脑上** | 立刻停下。告诉他「我这个模式读写不了你硬盘上的文件，装不了」，让他换一个能读本地文件的工具。**这时候往下做任何一步都是白做** |
| `...\AppData\Local\Microsoft\WindowsApps\python.exe` | **微软商店的占位符**，跑起来无输出、退出码 1，不是真 Python | 真没装。让他装（python.org 或商店都行），勾「Add to PATH」，装完回来重跑这一项 |
| `...\Programs\Python\Python3xx\python.exe` 或某个工具自带的运行环境 | 装了，但**不在你这条 PATH 上** | 用**绝对路径**跑：`"C:\...\python.exe" 00_原著/_gate.py`。比让他改 PATH 快得多，也不会改坏他的环境 |

**同一格还有个没写的兄弟：`git`。** 上面只教了 python，可后面的 `.git`、钩子、提交全踩着 `git` 走。
`git --version` 打不出来 → 先解决它，别往下走；找不到就怀疑这个命令不在 PATH 上，**不要怀疑包**
（2026-11-02 实测：某机器上 `git` 在 `PortableGit\versions\1.3.0` 里，递归搜索都没找到——它在 PATH 之外活着）。

**这一条是 2026-11-02 实测出来的，不是设想**：某 agent 报「你的电脑上没有安装真正的 Python」，
而那台机器上确实有一份（在工具自带的运行目录里，不在用户 PATH 上）。它没有说谎，也没有说全——
**而这种「半个真相」会让人去重装一个已经存在的东西**，然后以为装了两份是正常的。


### 1.2 「能读」不等于「能写」——装包几乎全是写操作

装这套东西要做的事：写 __NFILES__ 个文件、建 `.git`、十来个脚本其中一半会生成新文件、一次提交。
**全部是写**。所以第 5 项不过，后面每一步都会以某种方式失败，而且失败得不像它。

| 现象 | 说明什么 | 怎么办 |
|---|---|---|
| 建不了／只能建在别的目录（如它自己的会话目录） | 它在沙箱里，写权限被限制在固定位置 | 让它说清「批准一次是只管这一次，还是以后一直能用」。只管一次 → **换工具**：装一套要写七十多次，等于让人按七十次手印 |
| 能建但读不回 | 写的不是同一个位置（虚拟文件系统） | 同上，换工具 |
| 建、读、删三步都成 | 可以继续 | 继续第 2 项 |

> **判据**：不要问它「你能不能写」，让它真写一次。**能读不等于能写，这两件事在沙箱里是分开授权的**
> （2026-11-02 实测）。

**但「能写」还得看写给谁。** 2026-11-02 一次实测指出一个文档没写的分支：
同一个 agent，装进**你指定的文件夹**要按七十多次手印；装进**它自己的会话目录**则是零手印——
七十多个文件、`git init`、钩子、十几个生成物，一次审批都没有。**它能装，只是装的是另一块地。**
所以这里的分水岭不是「能不能写」，是「**出口在不在它默认能写的地方**」。

| 它说的 | 实际发生了什么 | 你怎么判 |
|---|---|---|
| 装在你给的文件夹里，每步都弹审批 | 沙箱逐次审批 | 问「批准一次只管这一次，还是以后一直能用」。只管一次 → **换工具**，或先让它要到一次长期授权 |
| 装得飞快、一次没问，但路径在它自己的工作区／会话目录下 | **装到它自己的地盘**了 | **不算装上。** 让它把那个绝对路径贴出来，你亲自去打开；打不开就是这个项目有一份副本在你拿不到的地方，白装 |

**第 3 项要特别说明，不然你会误判包坏了**：

`00_原著/_redline.py` 是「版权红线检查」，它要求根目录有两份文件（红线原则、发布检查清单）。**打包时会放空白模板进去，所以它应该通过。** 如果它说「缺 2 份」，说明打包时漏了模板——这是包的 bug，不是环境问题，要报给做包的人。

### 1.3 一条命令验整包：`python 00_原著/_selftest.py`

自检测的不是用户的稿子，是**这 __NSCRIPTS__ 个脚本自己还灵不灵**（构造已知会翻车的迷你项目，看它认不认得）。
它跑完只打一行小结，长这样（**具体数字以你机器上跑出来的为准，别背下面这行**）：

```
小结：用例 N 条 ｜ 过 N ／ 败 0 ｜ 真项目集成：绿 N ／ 报红已核 N ／ 需人看 N ／ 问题 0
```

`需人看 N` 那一格有时不出现——没有这种脚本就不打，不必去找它。五个状态这样读：

- **过 N ／ 败 0** —— 用例全过。有「败」就是包的 bug，报给做包的人。
- **绿 N** —— 这么多个脚本正常跑完。
- **报红已核 N** —— 这些脚本退出码非 0，**它自己说缺某个文件，而那个文件确实不在**
  （新建的空项目里缺台账，正常）。行内会写 `报红·缺 xxx.md，确实不在`。
  **这不是通过，是「它拒绝得有道理」。**
- **需人看 N** —— 这些脚本退出码非 0，但**机器核不出它为什么红**：可能它只是顺嘴提到一个
  不存在的文件，也可能它点名的文件其实都在。**可能拒绝得对，也可能判据错了**——扫一眼，
  别当成通过。
- **问题 N** —— 必须为 0。它抓两种：报了绿却没说查了多少、报了红却一个字都没点。

> **别把「问题 0」念成「全都过了」。** 真项目集成那一截最多有四个数并列（绿／报红已核／需人看／问题），四个加起来才是全部。
> 有人问过「是不是所有退出码 1 都这样归」——答案：不是自动归的。
> 报红要能点出一个**真的不存在**的文件才算「已核」；点得出但核不实的进「需人看」；
> 一个字都不点的才算「问题」。

## 二 · 问用户三件事（只问这三件）

一次问完，别挤牙膏。

```
1. 这个项目叫什么名字？（随便起，以后能改）
2. 你手上现在有什么？

第 1 问就已经答了——照原样再问一次，他会以为你没听，或者以为你要改他刚说的话。

逼一个不懂的人做技术选择，就是把他挡在门外。

## 三 · 建立工作区

包里的目录结构已经建好了。你要做的是**让它能跑起来**，不是从零搭。

按顺序做，每步做完确认一下：

```
1. git init                          （如果目录里还没有 .git）
   **然后配一次身份——全新机器上第一次提交会卡在这里**，报
   `Author identity unknown / unable to auto-detect email address`：

   ```
   git config --local user.name  "你的名字"
   git config --local user.email "you@example.com"
   ```

   先 `git config user.email` 试一句，能打出来就说明这台机器已经配过，跳过。
   **用 `--local`，不要 `--global`**：这套东西只在这个项目里提交，别去改用户的全局配置
   （2026-11-02 外部实测：文档原先整篇没提这一步，那位 agent 自己补的，它做对了）。
2. 装门禁钩子：
   把 scripts/git_hooks/pre-commit 复制到 .git/hooks/pre-commit
   （Git for Windows 不需要 chmod，WSL/macOS/Linux 要 chmod +x）
   ⚠ 钩子由 git 用 `sh` 执行。**找不到 sh.exe 的表现是「提交直接被拒」**，
     不是「门禁报错」——Git for Windows 自带它，把 Git 的 bin 目录加进 PATH 即可。
   ⚠ 钩子里调用的是 PATH 上的 `python`。如果你的 python 只在绝对路径下可用，
     先 `export GATE_PYTHON=<解释器全路径>`（或 Windows 下 `set GATE_PYTHON=...`）。
3. 填项目名（**不用改任何代码**）
   项目名只有一个来源：`00_原著/_pname.py`。它按顺序认第一个能读到的：
     ① 环境变量 `GATE_PROJECT`
     ② `README.md` 顶部那行「> 项目：XXX」
     ③ `00_原著/` 下有没有 `*_世界观设定集_v1.0.md`——有，就用它的前缀
     ④ 三处都没有，一律当「某项目」
   **推荐**：把设定集命名成 `<你的项目名>_世界观设定集_v1.0.md` 放进去，名字自动对上。
   **只写一处，别三处都写。** 正常项目写 README 顶部那行或设定集文件名（二选一）；
   **做验收／试装时只写 README**（`> 项目：测试项目`），**不要顺手设环境变量**——
   环境变量只活在这台机器的这个终端里，你一旦忘了它设过，后面看报告会以为名字是从文件读的。
   填完跑一句 `python 00_原著/_pname.py`，它会告诉你「项目名是什么、从哪读来的」。
   再跑一句 `python 00_原著/_pname.py --check`：白名单外应当是 0 处。不是 0，说明哪个脚本又把名字写回去了。
   （2026-11-02 外部实测：名字原先散在 6 个脚本里各写死一份，用户换名字就永远红）
   ⚠ **改名之后，设定集文件名要跟着改。** 真相源里那三份设定集的路径是「项目名 ＋ 后缀」拼出来的，
     名字变了、文件名没变，`_view` 的真相源那项就会按新名找不到（报 `setting 0/3`）。
     **那不是包坏了，是真话**：清单认的名字和你手上的文件名对不上了。改文件名，或者把 README 那行改回去。
4. 装 skill：python 00_原著/_skill_sync.py --list
   →  **只看它每个 skill 的第一行「本机状态」**：
      「**未安装**」→ 可以执行 `--install`
      「**已装且一致**」→ 不用动，跳过这一步
      「**已装但不一致**」→ **先别盖**，问做包的人（包里是脱敏版，盖掉的是本机可能正在用的那份）
   （2026-11-02 起它会自己先看一眼：目标已有别的版本就**拒绝**并列出差异，要盖得加 `--force`。
     已经装过就跳过：这一项会红，红得对，不影响其余九项）
5. 第一次提交（**会被钩子拦下来，这是预期，不是失败**）：git add . && git commit -m "初始化"
6. 跑一次：python 00_原著/_gate.py
```

> **它第一句如果是「这套东西还没装完（退出码 3）」**：那是上面第 1、2 步漏了，**不是包坏了、也不是内容有问题**。
> 它会直接点名缺哪一步，十项一项都不跑——补齐再跑一次。
>
> 反过来，**装完了的空项目**是另一种屏：十项全跑、报一堆红、最后说「新项目第一站，现在一项都不用修」。
> **这两屏不一样，别混**：一个在问「你装了吗」，一个在说「你装了，还没开始写」。

> **⚠ 如果你是在「已经用过这套框架」的电脑上试装**（比如在做验收测试）：第 4 步**一律跳过**。
> 包里那两个 skill 是脱敏版（角色名换成了「角色甲」），`--install` 会把本机正在用的那份覆盖掉，
> 而且**不会报错**——本机 skill 从此变成占位符，你要等到哪天 AI 说漏嘴才会发现。
>
> 2026-11-02 起 `--install` 会**自己拒绝**这种情况（列出差异、退出码 1，要盖得加 `--force`）。
> **但别把这条当保险**：它只认文件差，认不出你那份是不是真的在跑——跳过这一步仍然是对的。

**第 1 步不能省。** 整套框架靠 git 判断「什么改了、改之前是什么样」——没有 git，账实核对（`_diff`）和门禁钩子全都失效，等于只剩一堆 md。

**第 5 步看到什么算正常**：

**这一次提交会被拒绝，`.git` 里不会留下提交记录——这是走对了的样子，不是失败。**

（2026-11-02 外部实测：文档原先只写「第一次提交」，紧接着又写「9 红 1 绿是正常的」，
读起来像「提交成功了但报告很红」。真实顺序是**钩子跑完就拒绝了这次提交**，两者是同一件事。
那位 agent 按字面预期它会成功，跑出来才发现被拦。）

**十项里绝大多数是红的，只有一两项绿。这是正常的，不是包坏了。**

绿的那一两项，恰恰证明**包是完整的**：

· **版权红线** —— 这项检查要求两份文件在场，缺一份就红；它绿，说明包是齐的。
· **skill 同步** —— **只有第 4 步真装上了技能才绿**。要是你跳过了第 4 步（老机器、
  本机已有同名技能），这项会红——**红得对，不影响其余各项**。
  （2026-11-02 外部实测：这条红会让 agent 反复犹豫，因为文档一处说「跳过」、一处说「跳过会红」。
  两句都对——**跳过是动作，红是结果**，不是矛盾。所以：照抄结论，别修它。）

**别加 `--no-verify` 硬闯。** 空项目被拦是对的——它拦的是「还没有东西可核」，
不是「你做错了」。等下面那张表里的东西建起来，这一次提交自然就能过。

其余那些红，是因为**它们要检查的东西还不存在**。逐项对照如下——**这张表就是你要给用户看的解释**：

| 红的项 | 为什么红 | 什么时候会变绿 |
|---|---|---|
| 真相源守门 | 还没有正文和设定集 | 建了第一卷正文 ＋ 变更记录 |
| 正文账实核对 | 同上 | 同上 |
| 作废词残留 | 还没有定论台账 | 建一份台账（可以先空着） |
| 引用锚点 | 规范里引用的项目文件还不存在（会报几十处「路径不存在」）＋**包内还会多报 4 处「锚点失实」**——那是脱敏把引文里的人名换掉了、原文又不在，回核不了，**不是你的错** | 建了那些文件 |
| 副本一致性 | 还没有多份副本可比 | 项目里出现第二份同源文件 |
| 层级纯度 | 还没有专名台账 | 建专名台账，填入你的角色／地名 |
| 旧常量残留 | 常量台账是空的 | 填了第一条常量 |
| 索引层校准 | 还没有世界表／人物表 | 建两张表 |
| skill 同步 | 本机还没把这个 skill 装进去（**第 4 步跳过时，这项红是预期的**） | 跑 `python 00_原著/_skill_sync.py --install`；不装也不影响其余 |

**判断标准只有一条**：报的错是不是「文件还不存在」。是 → 预期内。是 `Traceback` 或语法错误 → 真坏了。

> **但这条判断不要交给回执去做。** 「红得对」和「要修的红」在屏幕上长得一模一样，
> 而门禁自己在小结后面已经把话说了（「新项目第一站」「这 N 项红是因为还没有东西可核」）。
> **让门禁说，不要让人再归一次类**——人归一次就多一个出错的地方，2026-11-02 外部实测里
> 那位 agent 就是自己重新归了一遍，把「skill 未同步」单独拎出来问，而门禁本来没要求它这么做。

**别对用户报数字，自己数一遍再说。** 写死数字的文档会把人教错——2026-11-02 实测里，
同一份包有人跑出 9 红 1 绿、有人跑出 8 红 2 绿（区别只在第 4 步装没装 skill），
而文档当时两处都写着「9 红 1 绿」。
说这句：**「包是完整的（已经通过的那几项就是证明），其余在等你的内容——我们现在开始填第一项。」**

---

### 第 7 步 · 出一份「装完回执」（**你跑，他只转发**）

**这一步不许省，也**不许**交给用户做。** 装完不回执，等于这次安装没发生过——出了问题只有一句“好像有点问题”，查不动。

**三条不许（这不是客气，是设计约束）**：

| 不许 | 为什么 |
|---|---|
| **不许要求他判断**「哪个红是对的」 | 他是外行。让他判断，他只会回一句“看着不太对” |
| **不许要求他执行命令** | 他不知道什么时候跑、跑哪个、跑完看什么。**你跑** |
| **不许要求他整理结果** | 让他总结＝让他重新理解一遍＝他放弃 |

**他唯一会做的动作是复制粘贴。所以整个验收必须只需要复制粘贴。**

回执**整段裸文本，不含任何装饰**，他长按全选就能转。格式固定七条，**每条都能从某条命令的输出里原样摘到，不给你发挥空间**：

```
【装完回执 · <包名，读 文件清单.txt 第一行>】
1 版本：<文件清单.txt 第一行原样>
2 我走到第几步：<1–7，哪一步停过就在后面写「停过」>
2b 装到哪：<绝对路径，必须是我自己在资源管理器里能打开的那种；出现 AppData／Temp／sessions／以点开头的隐藏目录／一串数字编号，就是装进了临时目录，照实写>
3 门禁十项：<python 00_原著/_gate.py 输出里的「小结」那一行，原样贴，别改写>
4 红项分类：<照抄，不要自己归类——把门禁收尾那两三行原样贴（「小结」后面那一段，
   尤其是「新项目第一站」或「N 项阻断」那几行）。只有出现 Traceback 才另贴那一段>
5 自检结论：<python 00_原著/_selftest.py 输出的小结那一行，原样贴>
6 我在哪一步犹豫过：<你自己答，一两句，说清犹豫什么>
7 用户说过哪些话：<把他在这次安装里说过的原话抄下来——**问句和指令都抄**，包括
   「装哪」「装好了吗」这种；一句问句都没有就写「本轮 0 句问句」，并把他的指令照抄两句>
```

**第 6、7 条是整份回执最值钱的部分，别嫌麻烦。**

- **第 6 条**：你的犹豫点，就是文档的漏洞位置。你没把握的地方，下一个外行也没把握。
- **第 7 条**：**用户问过的问题，就是真正的卡点。** 他问「全部复制还是只复制一部分」——那不是他笨，是文档没写清“复制到哪为止”。而他问完就过去了，你要是不抄下来，这条卡点五分钟后就蒸发。
  **别指望他记得，翻对话记录抄。**

> **只补回执、不想重装的现成话术**（已经装完的机器也能用，发给他就行）：
>
> ```
> 你那个已经装好就不用动了，帮我出个回执，我这边要知道装成了什么样。
> 按你那份 安装.md 里的「第 7 步 · 装完回执」做，七条全填。
> 第 6、7 条别省：第 7 条把我们这几天的对话里我问过的问题，原话抄下来。
> 出完把整段贴给我，不用解释。
> ```

**收到回执之后你才许判断这次试装算不算过**——判据不是“他没抱怨”，是第 3、4 条长什么样。
2026-11-02 实测里，同一份包有人跑出 9 红 1 绿、有人跑出 8 红 2 绿，**只有回执能看出是哪一种**。

---

> **状态源是他自己要建的东西，别替他编。** `Agent框架/状态源.json` 记的是他的进度，
> 我们不知道他走到哪。缺了它 `_view.py` 会明确说「找不到状态源」，这是对的。
> 他要出那张位置图时，把 `使用说明.txt` 第六节那两段最小样例给他（状态源 ＋ 待拍板队列）——
> **四个顶层键：环节／层级／断点／下一件事**，少一个脚本会提示「缺哪个、按空处理」而不是崩。

## 四 · 告诉他「现在该干什么」（别让他自己去读文档）

**这一步是整套安装里最容易做错的。**

做完 §三，用户面前是 30 个 md 文件。你要是说「你可以先看看 `Agent框架/README.md`」——**他会在第三步放弃。**

正确做法：

1. 你自己去读 `Agent框架/12_人话对照_v1.md` 的 §零点（那里按「你手上有什么」分了四条启动路）
2. 按 §二 第 2 问的答案，找到他对应那一条
3. **用一句人话说出来**：「你现在该做的是 ___，具体说就是 ___，做完把 ___ 给我」
4. 不要贴文件名，不要让他自己去翻

**AI 读文档，人只接一句话。** 这就是低门槛的全部操作。

## 五 · 你不许做的事

| 不许 | 为什么 |
|---|---|
| 改 `Agent框架/` 里任何一份规范 | 那是判据的源头。改了，后面所有检查都不作数，而且没人知道它变过 |
| 编造台账内容（作废词、常量、专名） | 台账是「出过错才记」的东西。编出来的假条目会让检查器误报，比空着更糟 |
| 跳过 `_gate.py` 直接开工 | 门禁十项里有一项是「账实核对」，跳过一次，后面就不知道基线在哪 |
| 把「⚠ 提示」当成错误去「修」 | 提示是检查器在声明自己的能力边界，不是它发现了问题 |
| 删掉那些断链的引用 | 那些引用指向用户还没建的项目文件。删了，规范就和项目脱钩了 |
| 在用户没要求时引入新的第三方依赖 | 这套东西的唯一依赖是 Python 标准库。多一个依赖就多一道安装门槛 |

## 七 · 如果装不上

先分清是哪种「装不上」：

| 现象 | 性质 | 怎么办 |
|---|---|---|
| 一堆「文件不存在」 | **正常**，项目文件还没建 | 不用管，继续 |

## 八 · 已经在用的机器上重装／升级（**先读这一节，再解压**）

> **这一节不是在讲「怎么装第二遍」，是在讲「怎么不把第一遍攒的东西弄没」。**
> 解压工具遇到同名文件**默认覆盖，不会问你第二次**。而包里带的东西有两类：
> 一类是**框架件**（本来就该被新版盖掉），一类是**状态件**（那是你的，不是包的）。
> 不清这两类就解压，第二类当场清零，**而且不报错**。

### 8.0 先选一条路，两条只走一条（**别把两条混着做**）

| | 做法 | 谁该走这条 |
|---|---|---|
| **甲 · 换目录**（默认走这条） | 新包解压到一个**新的空文件夹**，旧目录原封不动留着 | 所有人。**不需要搬任何文件**——因为压根没覆盖 |
| **乙 · 原地覆盖** | 先把三个状态件搬到包外 → 解压覆盖 → 再搬回 | 只有「路径不能变」的人（比如那个路径已经写进了别的脚本、快捷方式） |

走甲的人：读完 8.1 直接跳到 8.5（核验），8.2／8.3 是给乙用的。

**为什么默认走甲**：乙那套要求你在解压前先找到三个文件、复制到别处、装完再放回去——顺序错一步就白搬。甲只要一件事：**换个文件夹**。同样保得住东西，少三个容易出错的步骤。

**走甲之后还有一件事：旧目录里的东西要不要搬过来**（甲只把它们保住了，不会自动跟过来）：

| 搬 | 不搬 |
|---|---|
| 你的正文、设定集、定论台账、`99_过程稿/`，以及 `00_原著/` 下你自己写的部分 | `.git/`（两段历史混在一起，以后账实核对比的就是被污染的基线） |
| 你自己加的素材、参考图 | `[视图]*.html`（旧视图是按旧内容生成的，搬过来就是一张过期件） |

**分不清是框架件还是内容件的，先别搬**——列出来问做包的人，或者两边都留着。搬错方向不会报错，只会让下一次核对对不上。

### 8.1 解压前：先在目标文件夹里搜这两样，搜到就换地方

```
Agent框架/        ← 搜到它，说明这个目录里已经装过一套
00_原著/          ← 同上
```

**搜到任何一个，就不许在这里解压。** 换一个空文件夹解压，旧的那个目录原样留着当备份。
理由很直白：包根目录里就是这两个名字，解压到已经装有它们的目录上，等于整包覆盖。

### 8.2 只有走乙（原地覆盖）才需要：先搬出去的三个文件（顺序不能反）

| 文件 | 为什么 |
|---|---|
| `Agent框架/[台账]跟进通道.md` | 包里带的是**空白模板**，落位就是这同一个路径。不搬，你写的所有条目一次清零 |
| `00_原著/[台账]常量台账_v1.md` | 同上，你定的常量条目会没 |
| `发布前检查清单.md` | 同上，打勾记录会没 |

做法三句话：**复制到包外的一个临时文件夹 → 解压覆盖 → 再复制回来，覆盖包里的空白模板**。

> **为什么包会干这种事**：因为空项目要靠这些模板才能跑起来（否则门禁会报「台账不存在」的死链）。这是设计，不是故障——**但它只对「第一次装」成立，对「重装」是灾难。**

### 8.3 走乙的收尾：三条命令，缺一条就当没装好（**走甲的人跳过这一节**）

```
1. git add -A && git commit -m "升级前快照"      ← 解压【之前】做
2. （解压覆盖）
3. git add -A && git commit -m "升级到 <版本>（不含内容改动）"
```

**为什么非要分开两次提交**：这套框架靠 git 判断「什么改了、改之前是什么样」，账实核对全建在这上面。覆盖完直接 `git diff`，屏幕上是一片 `M`，**你分不清哪个 `M` 是你改的、哪个是版本升级带的**。以后每一次核对，比的都是被污染过的基线。

### 8.4 走乙才有的两件（**走甲的人不会遇到**）

**① 门禁钩子是「安装副本」，不是源文件。**
包里会覆盖 `scripts/git_hooks/pre-commit`，但 `.git/hooks/pre-commit` 是**第一次安装时复制过去的一份**，重装不动它。
结果：**门禁还是旧版，文档说升级了，实际拦你的是老规则。**

```
重装后重跑一次：把 scripts/git_hooks/pre-commit 复制到 .git/hooks/pre-commit
核对：diff scripts/git_hooks/pre-commit .git/hooks/pre-commit   必须无差异
```

**② 环境变量 `GATE_PROJECT` 会记着旧名字。**
如果上次设过，重装后项目名会读成旧的，设定集按旧名找不到，报 `setting 0/3`——**那不是包坏了，是名字对不上**。重装前清一次。

### 8.5 核验：用包里的 `文件清单.txt` 对两件事

包里有一份 `文件清单.txt`，第一行是版本号，后面每行是「sha256 前 16 位 ＋ 路径」。

- **核漏装**：清单里有、你盘上没有 → 解压不完整
- **核残留**：你盘上有、清单里没有 → 那是上一版删掉的文件。**解压只增不删**，它会继续被门禁扫到，报出「明明删了还在报红」的鬼

把这件事交给 AI 的一句话：

```
拿包里的 文件清单.txt 跟当前目录对一遍：列出①清单里有、盘上没有的
②盘上有、清单里没有的（忽略 .git、__pycache__、99_过程稿 下的备份）。
只列出来，先别删任何东西。
```

> **最后一句别删**：残留文件里很可能混着你自己新建的东西，第一遍只列不动，第二遍才决定删谁。
