## 一、先回答三个问题

这三个问题的答案，决定了后面所有的规则。**别跳过去。**

### 1. 你的故事，版权归谁？

- [ ] 完全归我（自己写的，没签任何平台）
- [ ] 归平台（签过约，需要回去翻合同里「独家」「授权范围」「改编」那几条）
- [ ] 和别人共有
- [ ] 不含故事，只是方法／工具

> **如果是第 2 种，先别往下做。** 平台合同里最容易被忽略的不是「版权归谁」，是
> 「**作者本人能不能在其他平台发布衍生内容**」。这条叫独占条款，它跟著作权是两件事：
> 你可能完全拥有著作权，但仍然不能自己去别处发（因为签了独家）。

### 2. 你打算把「这套文件」给别人吗？

- [ ] 不给（只自己用）
- [ ] 给，但是私有分发（授权几个人／私下传）
- [ ] 公开（任何人可下载）

> **「公开」这一项要特别小心。** 项目目录里的东西不只是代码——
> 里面的规范文档会逐条引用你故事里的原句、角色名、设定，
> 那些是**带原文的作品分析**，不是纯方法。公开它＝公开你的作品。

### 3. 成品（片子／图）要发出去吗？

- [ ] 不发
- [ ] 发，非商业
- [ ] 发，会挂车／挂课／有赞赏

> **「有收入」和「非商业」不能同时成立。** 一旦有进账，
> 之前所有「这是非商业展示」的定性都不作数了。

## 二、红线（按你上面选的填）

**把确定的事写在这里，以后不再讨论。** 写法要能一眼判断「违反了没有」。

| 红线 | 写清楚 | 为什么 |
|---|---|---|
| 什么绝对不能公开 | | |
| 什么可以公开、要带什么声明 | | |
| 仓库能不能改公开 | | |
| 能不能加协作者 | | |

**一条建议**：先按最严的写。**放宽很容易，收回来很难**——东西一旦出去，就收不回来了。

## 三、三条通用的坑（不管你上面怎么选，这三条都成立）

### 坑一：加 `LICENSE` 是在**授予**权利，不是在声明

仓库里没有许可证文件时，默认状态是「**保留所有权利**」——这是最严的状态。

加一个 MIT，等于告诉所有人「随便用、随便改、不用问我」。

**如果你想保留，就不要加。** 空着才是你想要的，不是忘了。

### 坑二：仓库设成公开，历史也会公开

不是「从现在开始公开」。**之前所有的提交、每一次改动的 diff、每一条提交信息，全部可见。**

如果你曾经在提交信息里写过「这段抄了某某」「这个角色原型是」，那些都会被人看到。

### 坑三：引原文做展示 ≠ 可以随便引

大多数情况下，**引用少量片段做评论／展示**是有空间的，但成立条件很窄：

- 片段要短，且**不能替代原作**（不能让人看完你的片子就不需要看原文了）
- 要有明确署名和声明
- 不能提供获取原作的入口（不导流、不放链接）
- 不能有商业收益

**四条缺一条，性质就变了。**

> 更安全的做法：**一个原句都不引**，用一句话概括画面构想代替。
> 你的目的是展示流程，不是让人读到故事。

## 四、这份文件管不了的

- **合同的具体条款**——机器读不到你的合同，只能你自己翻
- **平台协议怎么解释**——那些条文有歧义，拿不准就去问，别自己推
- **某个引用算不算「替代性」**——这个要人判

**三条都判不了的时候，选更保守的那条。**
