# 待脱敏清单

> **这份文件是一次真跑 `_pack.py`、被 `_verify_package.py` 的 V3 拦下来之后写的。**

## 一句话结论

**一个写到一半的项目，通常没有「可以分发的通用层」，只有「带着项目实例的一整套东西」。**

这不是 bug，是事实第一次被量出来。在这之前，所有关于「给别人用」的讨论，都建立在一个没验过的假设上。

## 三类，处理方式不同

| 类 | 是什么 | 怎么处理 |
|---|---|---|
| **A 专名** | 人名、地名、组织名、物件名、世界内的技术／事件名 | 机器全词替换，词表见 `_nounlist.py` 三源 |
| **B 实例** | 规则说明里举的「我们项目当时怎么踩的」 | 保留结构、去掉具体名，或整段改写成「某次实测」 |
| **C 标准件举例** | 表格里拿项目内容当示例 | 换成通用示例，见下 |

## 一条踩过的坑：**不要把所有专名都换成同一个 `[专名]`**

第一版把每个专名都替换成 `[专名]`，V3 全绿。打开一看：

```
| | [专名]（零改造人类） | [专名]（高度机械改造） |
      ↑ 两列都叫 [专名]，读者分不清哪列是哪列
```

**按类别给替换词**：人名 → 某角色；组织 → 某集团／某家族／某教会；
地名 → 某城；物件 → 某物件。**要让人读得懂，不是让机器过。**

## 一条原则：脱敏不改源文件

脱敏只在**打包复制时**替换，源文件一个字不动。

为什么：若直接清空项目里的专名表，项目自己的检查器会立刻「查不出任何专名」——
**门禁变成零覆盖假绿，而且没人会发现**。所以脱敏是打包时的一道工序，不是对项目的修改。

## 怎么验

```bash
python packaging/_pack.py --dry-run          # 只列清单，不写文件
python packaging/_pack.py --out <目录>        # 真打
python packaging/_verify_package.py <目录>    # V3 专名 / V5 凭据 / V11 坐标
```

三关都过才算干净。**任何一关说「查不了」，都不许当通过。**

## 已知缺口（写在明处）

- **词表之外的组织名／别名查不出。** 这是工具的边界，不是 bug。
  所以 `_triage.py` 在词表不全时会拒绝给 `A`：宁可说不知道，不假装干净。
- **角色关系与关键情节不扫。** 那需要一份设定摘要做基准，成本更高；
  目前靠 E0·1 的三问由人判。
