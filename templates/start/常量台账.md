# 常量台账（项目里「数字」的唯一裁判表）

> **这张表管数字。** 写错的数字会长得像规格，不像错话——所以它需要一张专门的表。
>
> 例子：你的规则写着「首帧画幅 = 交付画幅」，一个字没错。
> 但三份文件里写死着旧数字。照它做，整批重画。**规则没错，数字错了。**

---

## 怎么用

1. **发现一次数字对不上，就往这张表加一行**。没出过错的不加。
2. 「已作废的值」填**旧的那个数**（可以一行填几个，用 `;` 隔开）。
3. 以后全库扫到旧值就报红——除了「跳过」列里写的那些词所在的行。

**判据在表里，不在代码里。** 改口径只改这张表，不用改脚本。

---

## 一、常量规则

| ID | 常量 | 已作废的值 | 现用值 | 跳过（行内含这些词不算） | 说明 |
|---|---|---|---|---|---|

> **表里现在一行都没有，这是对的**——你还没配过任何常量，脚本会报「台账里没有规则」，
> 那是「待配」，不是「配错了」。
> 
> ⚠ **别填只带 ID 的空行**（`| C-01 |  |  | … |`）。那种行能让脚本报「台账本身有问题」，
> 把「待配」说成「配错」，红得对但话说错了。（2026-11-02 实测报上来的，`G-140`）
> 要用的时候直接照着上面表头写一行真数据。
>
> **不要照抄别人的数字。** 每个项目的规格不同，抄来的是别人的。

**「跳过」列填什么**：论证一个旧值为什么被废弃时，那段话里必然出现旧值。
把这些标志词（比如「作废」「原处」「教训」）填进去，那一行就不计错。

---

## 二、豁免（整份文件不算错，但限次数）

有些文件里的旧值是**合法的**——比如「形态对照表」里列出多种可选规格，或者一个让用户自己选的填表工具。

| 范围 | 理由 | 不超过 |
|---|---|---|
|  |  |  |

> 「范围」写文件路径（相对项目根）。「不超过」写个数——**不写就是无限，等于豁免失效**。

---

## 三、这张表管不了的

- **机械对比**：文档里的说法会不会跟着数字一起改，它不管
- **该不该改**：它只报「旧值还在」，不判「这个位置该不该用新值」
- **语义**：「这个数字在这个语境里是不是同一个意思」——这个要人看
