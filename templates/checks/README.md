# 通用检查器模板（`_links`／`_orphan`／`_diff`）

> **层**：**通用层**——整份可搬。这两支是最小的一对：一个查「写下的路径还在不在」，一个查「谁都没提过的件」。两份各管一件事，可以只拷一份。
> **用途**：新项目接框架时，**先搬这两支**，因为它们只依赖目录结构，不依赖任何业务字段。

## 怎么用（三步）

1. 把 `_links.py`／`_orphan.py` 复制到 `<项目根>/scripts/checks/`；
2. 复制 `checks.config.example.json` 成**同目录**的 `checks.config.json`，按本项目改：
   - `links.skip_ref`：哪些子目录里的路径是「目标状态」而不是本仓库路径（比如装好之后的说明）；
   - `orphan.skip_dirs`：归档区、备份区——那里的件「没人引用」是正常的；
   - `links.allow_file`：豁免清单，**没有理由的行不算**。
3. 跑：
   ```bash
   python scripts/checks/_links.py  --root .
   python scripts/checks/_orphan.py --root .
   ```
   `--root` 不给时默认取脚本上两级；`--config` 不给时取同目录 `checks.config.json`。

## 验收：**通用版与原版必须逐条一致**

脱参数不是重写。搬完要在原项目上跑一次对比：

```bash
python templates/checks/_links.py  --root . --config <原项目的等价配置>
python 00_原著/_links.py
```

- 结论行数字相同（本项目：`2072 条候选路径全部存在／20 处提示`）；
- 孤儿清单**逐条**相同（本项目：34 份，同一批）。

**数字相同但清单不同，也是失败**——那说明两版判据已经分叉了。

## 两条设计约束

1. **缺省值必须能独立跑**：没有 `checks.config.json` 时，脚本扫全库、不跳任何项目目录——**宁可多报，不许静默少报**。
2. **配置只放"哪些目录不查"，不放"哪些条目不算"**：后者要走豁免清单（带理由），否则判据会被人按需要改松。

## 哪些能搬、哪些不能（2026-11-16 实测三支，结论不同）

| 检查器 | 能不能脱参数 | 判据 |
|---|---|---|
| `_links` | ✅ 能 | 判据是「写下的路径在不在」——**跟项目无关**，配置只有"跳哪些目录" |
| `_orphan` | ✅ 能 | 判据是「有没有人提过它」——同上 |
| `_diff` | ✅ 能 | 判据是「改动有没有登记」——项目数据只有"哪几卷、三件套叫什么" |
| **`_anchor`** | ❌ **不能** | 判据本身就是**本项目的引用语法**：`卷X`／`第X章`／`K12`／`§五`／`6.5.1` 各指向哪一类真相源。换项目，`PREFIX` 全套要重写、`TRUTH` 要重判——**那不是脱参数，是重写判据** |

**`_anchor` 能搬的是「方法」，不是代码**（已写进 `Agent框架/18_检查器契约_v1.md`）：

1. 引用要**逐字命中**真相源，不许"意思对就行"；
2. 分三档：失实（找不到）／近似（压缩引用，可接受）／弱依据（大幅意译，有出处但不是原话）；
3. **短于 8 字不校验**——多半是术语或概括，校验它只会制造误报；
4. 豁免要**带理由**，且按文件列，不许按目录一刀切。

> **一条通用教训**：脱参数之前先问「这条判据是在描述**世界**，还是在描述**这个项目的写法**」。前者能搬，后者只能搬方法。

## 拆分大脚本的两支工具（2026-11-17 加）

一个检查器长到几千行、几十项之后，要拆。**别手搬**——手搬必踩三个坑（见 `18` §八·四）。

| 工具 | 干什么 | 怎么跑 |
|---|---|---|
| `_depmap.py` | 依赖归属图：ast 算「这项检查独占哪些名字、共用哪些」 | `DEPMAP_ROOT=<项目根> DEPMAP_PKG=<根>/00_原著/checks python _depmap.py` |
| `_mvchecks.py` | 搬运器：算闭包、按 ast 节点切、按字节改写 | `MV_ROOT=<项目根> python _mvchecks.py --to checks/xxx.py --names check_a,check_b --inject CASE,README --apply` |

**顺序**：先 `_depmap` 看边界 → 再 `_mvchecks` 搬一批 → **跑全量对比**（结论必须一致）→ 自检 → 提交。**一批一提交**，回退点也就一批。

**它救不了的三件事**（仍要人看）：

1. **分组是不是对的**——工具只知道「谁用了谁」，不知道「这些检查该不该归一组」；
2. **搬完的模块名对不对**——按词汇表起名（`sheet`／`views`），不按功能起名（`misc`／`utils`）；
3. **提示有没有变多**——多出来的提示可能是真问题（本项目搬完就暴露一处 `import` 路径错，一直静默降级）。
