# shapes/ —— 流程与判据的**形状**

> 这一层的唯一主张：**给你一副骨架，你可以不用；但不该因为在你这儿用不上，就让你连骨架都得自己造。**
>
> **不强制。** 五份之间没有依赖，可以只拿一份，也可以只看不抄。

## 它和另外两个目录的分工

| 目录 | 是什么 | 填了没有 |
|---|---|---|
| `rules/` | **判据**的形状（一条规则要哪些参数） | 形状空着，绑定你自己填 |
| `shapes/` | **流程**的形状（一个环节要什么、什么算完） | 全是空表格 |
| `Agent框架/` | **已经填好的那一份**：某个人真跑过一遍的流程 | 填满了，但那是**他的**填法 |

三者的关系一句话：**`Agent框架/` 是答案，`shapes/` 是题目。**

先看答案会以为「只能这么做」；先看题目才知道「哪些是必须的，哪些只是他的选择」。

## 哪些必须守，哪些可以裁

这三层要分开看，混在一起就会变成「要么全做，要么不做」。

| 层 | 内容 | 能不能裁 |
|---|---|---|
| **① 顺序** | 先定范围 → 再定位置 → 再写提示词 → 再花钱 → 再判 → 再收口 | **不能裁。** 判定不能跑到产出前面 |
| **② 三个不可逆点** | 投喂定级（防不可逆泄露）／三表核对（防精修错答案）／花钱前公示（防重复花） | **不能裁。** 它们拦的东西不会自己恢复 |
| **③ 细节** | 判据九格、交接四段、闸三档、纠错四列 | **能裁。** 裁了只是慢或返工 |

第 ② 层就是「大环节必须守」的准确说法：**守的不是九个环节全做满，是这三处不许跳。**
其余环节可以合并、可以后补——等你被返工咬过一次，再补，那时你知道它防的是什么。

## 怎么取用（三档，随便挑）

1. **只看**：读一遍，知道一个完整流程要考虑哪些环，然后按自己的方式做。
2. **抄一份**：把某一份复制到自己仓库，把空表格填上，其余不管。
3. **接进闸**：想让机器替你盯，就把 `rules/` 的引擎接上，`shapes/` 里的表变成它的绑定。

## 一条边界

`shapes/` 里**不写任何具体项目的名字、编号、文件路径**。
判断办法：贴给一个没读过原项目的人，他能不能填自己的？能，才合格。

## 目录

| 文件 | 回答什么 |
|---|---|
| `01_判据形状.md` | 一条判据要写清哪几件事，才不会「看着像判过了，其实什么都没拦」 |
| `02_环节形状.md` | 一条产线最少要有哪几环，每环的入口出口是什么 |
| `03_交接形状.md` | 换人接手时，靠什么把「现在在哪」传过去 |
| `04_闸形状.md` | 什么该拦、什么只提示、什么该明说「我没查」 |
| `05_纠错形状.md` | 一次判错怎么记：四列，第四列「如果重来在哪一步能拦住」才是资产 |
