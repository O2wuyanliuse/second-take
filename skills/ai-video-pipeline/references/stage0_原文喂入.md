# 环节 ⓪：原文与设定底稿喂入

> 这是整条链的第 0 步，也是**最容易因为"想省事"而跳过、结果后面全乱**的一步。
>
> 一句话定位：**开始任何"小说→AI 视频"项目之前，先把「原文 + 已有设定」喂进来，落成一份能反复引用的底稿，并把底稿和已有设定对齐。**

---

## 为什么必须有这一环

之前在某长篇项目上踩过的坑，本质是同一个：

- **我手里没有原文，只有你一句一句喂的碎片** → 每次你抛一句、我补一段、你再纠错，来回烧轮次、烧积分、烧耐心。
- **线上版和本地版有出入** → 我用旧版判断，结果和你的最终版对不上。

这一环就是为了根治这个：**让"原文"和"设定"从一开始就落成文件，成为后面每一环都能引用的地基，而不是散在对话里。**

---

## 这一环做什么（四步）

### 第 1 步：喂入

- 把**任何可得的原文**读进来：本地 txt / md、线上发布版（浏览器读或用户复制）、甚至只有一个大框架的底稿。
- 把**已有设定文档**也读进来：设定集、角色卡、旧契约、交接说明——凡是之前沉淀过的，一起收。
- **铁律：可以不全面，但不能没有。** 有个大框架的旧版，也比"我脑子里有、你没读到"强。缺的细节，后面和作者一起补。

**喂入时，先做「原创声明」（轻提醒，不设硬卡）：**

当使用者要开始一个「小说→AI 视频」项目时，在喂入原文的当口，主动问一句版权归属，做一次轻量提醒：

> 「请确认：这部小说的版权归您本人，或您已获得改编授权？（若是同人二创/公有领域/授权模糊，也请如实说明来源）」

这条是**伦理守门，不是拦截**——它不做「拒绝」的动作，只做「提醒 + 留痕」：

- **提醒**：让使用者意识到「改编前要先有授权」，避免无意识侵权。
- **留痕**：把使用者的来源声明（本人原创 / 已授权 / 同人二创 / 公有领域）写进项目档案，将来若有纠纷，能证明「工具方尽到了提醒义务」。

**真实边界（要诚实）**：这拦不住「铁了心要侵权」的人（对方撒谎说「是我原创」，无法证伪）。它守的是「工具方的伦理底线」——尽到「提醒 + 留痕」的尽责义务，不沦为「明知侵权还无脑帮做」的帮凶。想百分百拦截侵权不现实，尽到分辨义务是现实且必须的。

> 为什么选「轻提醒」而非「硬关卡」：工具定位，不误伤灰色地带（同人二创、授权模糊），同时守住伦理底线。

### 第 2 步：落底稿

- 把原文落一份到项目 `00_原著/` 下，命名能看出"这是哪个版本"（如 `正文_原始稿.txt`、`线上版_第二卷.txt`）。
- **版本要分清**：原始稿、发布版、润色稿是不同文件，别覆盖。如果线上和本地有出入，**以线上为准**，但本地稿留着做对照。

### 第 3 步：统合对齐 + 扫雷

把「原文」和「已有设定」对着看，产出三张清单：

1. **哪段原文对应哪条设定**（已对齐，不用动）
2. **哪些设定在原文里没出现 / 对不上**（可能是设定超前了，也可能是原文改了）
3. **哪些原文细节还没进设定**（要补）

这一步的价值：**让"文本"和"设定"指向同一份东西，而不是两个版本各说各话。**

**在这一步里，做一件「扫雷」的活（只列清单，不裁决）：**

通读完原文后，我（AI）**无法分辨**以下几类情况，它们从文字表面看几乎一模一样：

- 作者**笔误**（写错了，但本人没发现）
- 作者**笔力不够**（想写但没写到位）
- 作者**故意埋的文字伏笔**（藏着等后续回收）
- **钩子未回收**（前面埋了、后面忘了揭）
- **遗漏**（该写但漏了）
- **烂尾**（写了开头没下文）

**环节 0 只做「扫雷」：把这类「读起来不对劲、有猫腻、缺一块」的地方，逐条列成「扫雷清单」，每条标上候选性质，但不裁决。**

- **裁决是环节 1 的活**：扫雷清单交给环节 1，在补设定的过程中同步逐条裁决。
- 为什么不在环节 0 裁决：**排雷的答案，往往就是「设定补充」本身**（比如「两个神是什么关系」——排雷结论就是一条新设定）。把排雷和补设定放在一起，才协同；分开，补设定变凭空写、排雷变孤立改 bug。

### 第 4 步：移交

- 把「底稿 + 对齐清单 + 扫雷清单」打包，作为环节 1 的输入。
- 扫雷清单里**不要求作者当场裁决**——裁决留到环节 1，跟设定补充一起做。

---

## 关键原则

1. **这一环不复杂，只是时间上久一点。** 它的核心是「沟通 + 统合 + 扫雷」，不是「创作」。久一点没关系，因为它是给后面所有环节省时间。
2. **这一环可以顺带做文本续写 / 改动。** 如果作者在统合过程中发现原文某处要改、要补，我可以在征得作者同意后直接给出续写或改动建议。**但前提是"和作者沟通好"，不是我擅自改。**
3. **版本以线上为准。** 遇到"本地 vs 线上"冲突，先问作者哪个是最终版，别擅自用旧的。
4. **底稿是可引用的资产，不是一次性消耗品。** 落盘之后，后面分镜、写提示词、查连续性，都回到这份底稿，不再靠对话记忆。
5. **环节 0 只「扫雷」，不「排雷」。** 我通读原文后，凡「读起来不对劲」的地方，一律列成「扫雷清单」标候选性质——**不裁决**。裁决是环节 1 的活，跟设定补充同步做。

---

## 放行条件（⓪ → ①）

- [ ] **原创声明已做**（喂入时问过版权归属，来源声明已留痕进档案）
- [ ] 原文底稿已落 `00_原著/`（版本标注清楚）
- [ ] 已有设定文档已收齐
- [ ] 「原文 ↔ 设定」对齐清单已产出（对齐 / 冲突 / 待补 三类）
- [ ] **「扫雷清单」已产出**：凡「读起来不对劲/有猫腻/缺一块」的地方，已逐条列出并标好候选性质（伏笔/笔误/笔力/钩子未回收/遗漏/烂尾）

> 注意：扫雷清单**只需列出来，不需要在这里裁决**。裁决是环节 1 的事。

**没满足「原创声明 + 底稿落盘 + 对齐 + 扫雷清单」这几样，就不许进环节 ①**——环节 ① 补设定要基于"对的原文"，底稿没对齐、雷没扫出来，补设定就会带着隐患。

## 待回填

- 这一环**已在某长篇项目上跑过一遍实操**（读入三份底稿 → 落盘 → 统合对齐 → 排雷出 5 处矛盾 + 9 项待补）。但「排雷」这个机制是**这次实操才暴露出来的、刚补上的**，还没在完整项目上验证闭环。
- 等第 1 章走一遍「喂入 → 落底稿 → 统合排雷 → 补全」全流程，把实际踩到的坑（尤其是「排雷清单怎么列、怎么跟作者逐条过」的节奏）回填进来，再升格为固定步骤。
