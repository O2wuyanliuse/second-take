# 环节① · 文本设定（原著 → 改编地基）

> 前置：环节 ⓪ 原文喂入已完成（底稿落盘 + 对齐清单 + 扫雷清单）。见 `stage0_原文喂入.md`。
> 输入：已对齐的原文底稿 + 原著 + **扫雷清单**
> 输出：① 项目专属红线 + ② 角色/场景/道具设定卡 + ③ 扫雷清单全部裁决落盘 + ④ **世界观 ↔ 原文对齐清单（冲突清零）**
> 放行条件：原著关键设定逐条确认、扫雷清单逐条裁决、**对齐检查跑过且冲突清零**、角色落到"可画字段"，才进分镜；或按第 6 步转入「续写／扩写」。

## 本环节的工作流（六步，作者 2026-10-26 重定）

**先判断输入是哪种，走的分支完全不同。走错分支，后面全部白做。**

### 第 1 步 · 创作者喂原文

拿到原文。**先别动笔补设定。** 先问一句：你手里有没有已经写好的世界观／设定文件？

### 第 2 步 · 按「有没有世界观」分两种情况

**情况 A：创作者已经有世界观**（设定文件、大纲、笔记，哪怕只是零散的）

- 我的身份是**校订者，不是作者**——见 `SKILL.md`「有稿只校，无稿才写」。
- 只做两件事：**对照原文，指出冲突**；**指出缺什么、建议补什么**。
- **切忌自由发挥。** 任何没被明确要求的设定，都不许写进文档。
- 修改与补全**逐条推进、逐条请作者拍板**（见 `SKILL.md`「作者协作铁律」）。
- 目标是：**条目之间的逻辑，与原文或作者意愿没有重大冲突。** 不是"更完整"，也不是"更漂亮"。

**情况 B：创作者没有世界观，只有原文**

- 这时才可以**参照投喂的原文，较为自由地构建**——但仍要贴着它的调性、逻辑、线索，不是另写一个世界。
- 自由度只到「补全」，不到「改造」：**原文已经写了的东西，不许为了设定好看而改掉。**
- 同样逐条确认。

> **为什么这条要写死**：自由发挥出来的设定，往往比创作者自己的更好看——**因为它只对一处负责，不对全书负责。**

### 第 3 步 · 确认最终的世界观

逐条拍板完，出一份总览表（见本文第四节），让作者一次看全，而不是散在几十次对话里。

### 第 4 步 · 对齐检查：世界观 ↔ 原文

**这一步不能省，而且必须单独做一遍。**

用**冲突对照表**的形式（`SKILL.md` 交付规则第 5 条 + `references/table-view-template.html`），把世界观和原文逐条对：

- 世界观写了、原文反着写的 → **硬冲突**
- 原文写了、世界观漏掉的 → **缺口**
- 两边都写了、但不是同一件事的 → **错位**

**为什么要单独做**：世界观是**分条**写的，原文是**连续**写的。分成两条看时，每一节都自洽；摆到一张表里才现形。

### 第 5 步 · 协助创作者修改对齐

**不自己改。** 给出「**原处 → 建议改成 → 为什么**」，作者逐条点头再落盘。

改完**重跑第 4 步**——改动会带出新的错位。实测过一次改动产生 12 处连锁，其中 3 处是改出来的新问题。

### 第 6 步 · 收口问一句

对齐之后，问作者：

> **「要不要严格按这套世界观，把原文接着往下写、并把现有内容扩写？」**

- **要** → 转入「续写／扩写」模式，**严格守住已经拍板的每一条设定**，不许在写的过程中顺手改设定（改了就是绕过拍板）。
- **不要** → 才进环节② 分镜。

> **这一步是问，不是默认执行。** 作者可能只想把世界观改对，不想要续写——那就停在这里，别自作主张往下推。
> **这也是「条目没收口，不许提前铺下一步」在本环节的落点。**

## 排雷与补设定，同步进行（这是本环节的核心机制）

**「排雷」和「补设定」是一件事的两面，必须绑在一起做，不能分开。**

- 环节 ⓪ 只负责「**扫雷**」：列出清单，标候选性质（伏笔/笔误/笔力/钩子未回收/遗漏/烂尾），**不裁决**。
- 环节 ① 负责「**排雷**」：拿着扫雷清单，**在补设定的过程中同步逐条裁决**。

为什么必须同步：**排雷的答案，往往就是「设定补充」本身。** 比如「两个神是什么关系」——裁决结果就是一条新设定；「某角色的另一面」——裁决结果就是他人设的一部分。把排雷和补设定分开，补设定变凭空写、排雷变孤立改 bug。

> 为什么必须排干净才往后走：在原始剧本层没把雷排干净，后面每一环都在埋着雷的地基上盖楼——分镜会踩、提示词会踩、图片视频更是烧积分去踩。**排雷是后面省积分的第一道闸。**

裁决规则：

- 是「伏笔」→ 标「只埋不点」，进伏笔清单，等后续回收（不删、不改、不补）。
- 是「笔误 / 笔力不够 / 遗漏 / 烂尾」→ 问作者要不要补、怎么补，补进设定集。
- 是「钩子未回收」→ 标进「待回收清单」，别当 bug 删掉。

## 这一环的本质

**把原著从"文字"转成"AI 视频能拍的东西"。**

它分两层：

- **原著层**：世界观设定、文风红线、内容红线——**输入源**，是改编的地基，不是要重做，是要守住。
- **改编层**：把原著转成视觉锚点卡——**产出物**，后面每一镜都要引用。

**铁律：原著未定稿，分镜不许冻结。** 文本是地基，地基没浇完，楼不许封顶。

**环节① 的产出边界（越界自查）**：本环节只定两件事——**「世界是什么」**和**「正文怎么写」**。
**不定「怎么拍」。** 切点、景别、时长、运镜、台词与画面对打的具体设计，全部属于环节②（分镜调度）。
发现自己正在写镜头语言，就是越界了——哪怕标注了「留给分镜」。**先写下来再打个免责标签，不等于没做。**

## 通用 vs 项目专属

本 skill 是**通用流水线**，任何"小说→AI 视频/漫剧"都能跑。

- **通用方法**（本文件和 SKILL.md、其他 stage）→ 换项目不用改。
- **项目专属**（这部小说的红线、设定、锚点）→ 放在 `references/projects/<项目名>.md`。

**换新项目时，不要改通用层，而是新建一个 `projects/` 实例文件。**

## 二、改编层：人话 → AI 语言的转写器

**核心工具：角色设定卡。** 它的本质是"人话 → AI 语言"的转写——每一个字段，都在逼你把脑子里模糊的"气质清冷"，转成 AI 能稳定执行的"左眼下泪痣、右手腕红绳"。

**铁律：卡里每一条都必须"能被画出来"。写不出画面的词（气质、氛围、感觉）不进卡，只进风格层。**

### 角色设定卡字段（每个角色一张，先写死再出图）

| 字段 | 要求 | 好写法 | 废写法 |
|---|---|---|---|
| 角色ID | 英文短名，全程不变 | `mo_jin` | 主角 |
| 年龄/性别 | 具体 | 二十几岁 男 | 青年 |
| 头身比 | 数字 | 7.5 头身 | 正常比例 |
| 发型 | 长度+质地+分缝 | 略长黑发，凌乱 | 短发 |
| 瞳色/眼型 | 具体色值或对照 | 深灰，疲惫 | 有神 |
| 标志特征 | 1~2 个，必须可画 | 眼下青黑、胡渣 | 颓废 |
| 服装 | 件数+材质+主色 | 墨绿黑哑光机能夹克+灰蓝机能裤 | 机能风 |
| **禁用项** | 明确排除 | 不要高饱和、不要亮面皮 | — |
| 参考图 | 图号或链接 | `outputs/02_锚点/<角色>/<角色>_脸基准_v4.png` | — |

**禁用项要累积**：每次出图失败的原因，累积到 5 条以上就写进"禁用项"。这张卡不是记账，是 skill 的语料。

### 锚点不是一张图，是一组图（各有分工）

| 锚点类型 | 用途 | 注意 |
|---|---|---|
| 脸基准 | 锁脸 | 锁脸不锁表情，引用时补神态修正 |
| 全设立绘 | 全身服装 | |
| 半身 | 中近景 | |
| 三视图 | 多角度 / 查部件数量 | 比立绘清楚 |
| 手部锚点 | 拍到手的镜头 | 手最容易暴露年龄，要写独立规格 |

**设定图 ≠ 首帧图**：设定图是"结构卡"（查部件、查比例），首帧是"正在发生的一帧"（进视频）。两者不能互相替代。详见 `prompt-rules.md` 第 17 条。

## 三、工作方法（规则本体在 SKILL.md，这里只写环节① 的用法）

四条协作铁律的**正文**在 `SKILL.md`「作者协作铁律」：**逐条确认制 / 有子集必逐条确认 / 交账≠定稿 / 拒绝二分**。
**本文件不重复它们**，只写这四条在设定环节长什么样：

1. **这里的「一条」是什么**：一个主条目（如条目 8），或它的一个子条目（如 8.5）。**主条目拍板不算过，子条目要一条条过。**
2. **每个条目的固定节奏**：落盘设定集 → 交账（改了什么、依据是什么）→ 发问「**这条认不认**」→ 作者拍板 → 进度表才标 ✅。
3. **每条设定分两层**：世界内可见文本 ＋ 【设计说明】（元层面，不进作品）。设定要能被「为什么这么定」追踪。
4. **故意留白，不要填**：有些坑是设定的一部分，**不填**。不是所有缺口都要补。
5. **改动要更新进度表**：设定改了，所有引用它的地方要同步。
6. **越界线见本文件开头「环节① 的产出边界」**：这里拍的是**设定的表述**（这句正文这样写对不对），不是**它的实现**（这个镜头怎么拍）。

> **为什么这四条被搬到了 `SKILL.md`**：它们原先写在本文件里，结果后面几环没人读——**排在环节① 的规则，默认只能管环节①。** 而这几条管的是「怎么跟作者确认」，跟哪一环无关。任何一条规则写下来之前，先想清楚它到底管多宽。

## 四、设定基本完成时，必须产出「总览表」

**触发条件**：本环节的世界观条目补到**基本完成**——即绝大部分已 ✅、只剩一两条待定稿时。

**产出**：`00_原著/<项目名>_世界观总览表_v1.0.md`

**为什么必须有这张表**（三个都是真问题，不是锦上添花）：

1. **设定集是过程记录，不是结论索引。** 条目按「确认顺序」排列，读起来是流水账。改编阶段要查的是**结论**，不是当时怎么拍的。
2. **翻设定集太贵。** 一份写完的设定集动辄几千行，后面分镜、写提示词时每次回去翻，都是浪费。
3. **一张表能暴露矛盾。** 同一个维度写在两处、两处说法不一致，各看各的看不出来，摆进同一张表里立刻现形。**这是分层自检之外的第二道体检。**

**表的写法（硬要求）**

- **每个单元格必须能独立读懂**——不看设定集也明白。**宁可长，不许省。**
  > 这条是本规则的核心。过度精炼的表，半年后回看会产生新的误解，等于制造了第二个真相源。参照 `.ardot` 之外的所有参考文档：**缩写是给已经记得的人看的，而半年后的你并不记得。**
- **不用只有内部人懂的简称。**「三源」「两把锁」「A+C」这类，要么展开，要么当场加注。
- **每行末尾标对应条目号**，方便回查。
- **首行声明：本表是索引，不是正文；冲突以设定集为准。**（否则它迟早会长成第二个真相源。）
- **按「世界结构」分节，不按「条目顺序」分节。** 条目顺序是工作顺序，不是阅读顺序。
- 建议分节：一句话 / 时间轴 / 神与人 / 人的力量 / 世界的形状 / 世界的秩序 / 核心机制 / 留白清单 / 还没定稿的。

**「审校版」是必需品，不是加分项**

总览表第一次给作者时，**必然有一批格子是待确认的**。这种时候不要交一份「看着像定稿」的表，要交一份**审校视图**：

- 待确认的格子用**深色／彩色块 + 左侧竖线 + 编号（A1、B2 这种）**标出来。
- 顶部放一个**可点击的疑点索引**，点一下跳到那一格。
- **每个标注后面必须跟一句「问题是什么 + 建议怎么改」**——只涂颜色不给建议，等于把问题原样丢回去。
- 整块缺失的内容，用**虚线框占位**，别悄悄省略。
- 审校版文件名带日期，正式版带版本号，两份分开存。

做法见 `SKILL.md`「交付规则」第 4 条。**模板：`references/table-view-template.html`**——整份复制改内容，CSS 不动。
