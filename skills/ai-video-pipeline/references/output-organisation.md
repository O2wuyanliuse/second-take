# 产出归档规则

一份工作跑了几天之后，产出会从「三个文件」变成「一百多个文件」。
到了那个点，找不到东西的成本已经超过重新生成的成本。

所以从第一天就按这个放。

---

## 一、七层结构

```
outputs/
├── 00_索引.md          找东西的入口（按任务查，不是文件清单）
├── 01_导演表/           交付主件（表格、预览页）
├── 02_锚点/             定稿参考图，只引用不再改
├── 03_场景/             场景资产
├── 04_首帧/             可进视频生成的首帧
├── 05_提示词/
│   ├── 当前/            还会再用到的
│   └── 旧版/            被取代的，留着对照
├── 06_文档/             设定、报告、方案
└── 99_过程稿/           废稿、中间稿、验收对照、分析图
```

**编号不是装饰。** 它决定排序：`01` 永远是第一个看到的，`99` 永远在最后。
每天打开目录，眼睛先落在交付主件上，而不是一堆 `_zoom` 和 `v7_不通过`。

---

## 二、命名：`{对象}_{内容}_{版本或状态}`

| 好 | 不好 |
|---|---|
| `主角_脸基准_v4.png` | `参考图_主角_正脸基准v4.png` |
| `角色B_三视图_定稿.jpg` | `三视图_角色B_v3_通过_Pass1.jpg` |
| `LOC-B_场景名_v2定稿.jpg` | `场景_LOC-B_v2_通过.jpg` |

**开头两个字要能识别对象**——因为文件列表是按名字排序的，`主角_*` 会聚在一起，`参考图_主角_*` 和 `参考图_角色_*` 也能聚，但一旦混进 `三视图_角色B_*`，同一组就散了。

**状态词只用三个：`vN` / `定稿` / `通过`。** 不要「最终」「真的最终」「改好」「OK版」。

---

## 三、归档判断：三个问题

| 问题 | 是 → | 否 → |
|---|---|---|
| 这份东西以后会被**引用**吗？ | 进 `02/03/04` 或 `05_提示词/当前/` | 进 `99_过程稿/` |
| 它已经被下一版取代了吗？ | 进 `99_过程稿/` | 留在当前 |
| 它只是为了看一眼（验收、比对、放大检查）？ | 进 `99_过程稿/` | 留在当前 |

`99_过程稿/临时检查/` 可以随时整个清空，不影响任何东西。**这一条很重要**：它给了你一个「不用纠结、先扔这儿」的位置，否则人就会在删和留之间卡住。

---

## 四、索引文件要按任务写，不要按文件列

坏的索引：把 `ls` 的结果贴一遍。**那种索引没人看，因为你知道文件名就不用索引了。**

好的索引回答的是「我要做 X，用哪些」：

```
| 任务 | 用哪些文件 |
| 出主角的图 | 脸：A / 全身：B / 中近景：C / 多角度：D / 手：E |
| 查服装某部件在哪 | 三视图正面单人（比立绘清楚） |
| 查踩过的坑 | skill 的 prompt-rules.md（24 条，带证据） |
```

---

## 五、搬完之后必须做的事

1. **更新所有文档里的旧文件名引用** —— 用脚本做精确字符串替换，不要手改
2. **改生成脚本的输出路径** —— 否则下次重跑会把新文件吐在根目录，一夜回到解放前
3. **重建一次** —— 验证输出确实落在新位置

第 2 条最容易忘。**目录整理的保质期，取决于生成脚本有没有跟着改。**

---

## 六、什么时候整理

不要等到「乱得受不了」再整理。两个信号出现就动手：

- 根目录的文件**超过 20 个**
- 出现**第三个** `_zoom` / `_tmp` 之类的临时目录

整理一次大概半小时，但拖到一百个文件时，你会花两小时，并且中途会放弃。
